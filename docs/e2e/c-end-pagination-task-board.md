# C 端分页与 B 端任务看板 E2E 记录

> 2026-10-29 · 临时种子数据验证 · 不修改演示数据库

## 环境

```text
临时 C DB：tmp/c_e2e.sqlite
独立 API：127.0.0.1:8011
前端：web/dist
```

## 1. 店宠历史消息分页

种子：

```text
buyer_1 ↔ store_demo
25 条历史消息
```

步骤：

```text
打开 C 端 App
进入「山野户外旗舰店」
检查初始消息数
点击「加载更早消息」
再次检查消息数
```

实际结果：

```text
初始 20 条
加载后 25 条
去重后 25 条
「加载更早消息」按钮消失
控制台 0 errors
```

结论：before 游标分页无重复、无遗漏，前端按钮状态正确。

## 2. C 端审计分页

种子：

```text
buyer_1
25 条 CONFIRMED 订单
0 条报价
```

步骤：

```text
打开 /v2/#/admin/c-end
检查分页文本
点击「下一页」
检查页码与当前页订单
```

实际结果：

```text
第 1 / 2 页 · 订单共 25 条 · 报价共 0 条
点击下一页
第 2 / 2 页
当前页 5 条订单
上一页可用，下一页禁用
控制台 0 errors
```

结论：offset 分页与 totals 正确，筛选/分页控件联动正常。

## 3. B 端任务看板

实际结果：

```text
/v2/#/agent/actions 可访问
待确认 0 / 已确认 1 / 已完成 1
点击「标记完成」
→ 提示「任务已完成」
→ 列表刷新为已完成
控制台 0 errors
```

结论：任务看板能读取 `/api/agent/actions` 并调用 complete 接口。

## 4. 注意事项

- E2E 使用临时 SQLite 与独立 8011 端口，演示库未被污染。
- 审计分页的报价表在订单多、报价少时，靠后页可能为空，属于共用 offset 的已知设计。
- 任务看板本轮未覆盖移动端截图。
