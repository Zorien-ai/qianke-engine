# C 端“让小鱼去砍价”改为当前会话商品

日期：2026-11-12

## 问题

CApp 的“让小鱼去砍价”按钮此前硬编码：

```js
const NEGOTIATION_DEFAULT = { need: "跑鞋", budget: 500, quantity: 1 };
```

无论当前在哪个商家、聊的是哪个商品，都会拿“跑鞋 / ¥500”去谈判。

## 修复

点击“让小鱼去砍价”后打开砍价确认层：

```text
当前商家自动带上
商品从当前会话最后一条用户消息提取
预算只从用户自己的话里提取，没有则默认 500
数量默认 1，可修改
用户确认后按当前 merchant 发起谈判
```

商品名会做归一化：

```text
“这款明前龙井多少钱，有优惠吗？”
→ “明前龙井”
```

避免把整句问句直接交给后端导致“没有匹配商品”。

## 验证

当前会话为山雾茶业，最后用户消息提到明前龙井：

```text
弹层商品 = 明前龙井
弹层商家 = 当前商家 · 山雾茶业
预算 = 500
数量 = 1
```

![C 端砍价确认层](docs/e2e/c-negotiate-context.png)

实际请求：

```json
{
  "need": "明前龙井",
  "budget": 500,
  "quantity": 1,
  "friend_id": "store_tea"
}
```

谈判成功生成报价：

```text
小鱼：我想在 ¥500.00 内买明前龙井，数量 1
山雾茶业店宠：明前龙井，1 件，单价 ¥298.00
→ 生成结构化报价
```

![C 端砍价结果](docs/e2e/c-negotiate-result.png)

## 已知限制

1. 商品名提取基于当前会话文本，极端口语（“就那个”）可能需要用户手动修改。
2. 当前没有从 CShop 已选 SKU 传参到 CApp，跨页面砍价仍以会话上下文为准。
3. 预算默认 500，用户可在弹层修改。
