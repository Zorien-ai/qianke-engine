# 数据模型

> 依据：`src/rag_demo/db/schema.py`、`src/rag_demo/auth.py`、`src/rag_demo/config.py`。
> 目标读者：需要二次开发、做数据迁移或接企业数据源的工程师。

## 1. 总览

系统把数据分成两类，分别存放在独立的物理库中：

| 平面 | 数据库 | 用途 | 是否入库 |
|---|---|---|---|
| 公开演示 / 评测基线 | `vec_db` | demo 数据、离线评测固定数据集 | 源码与 demo 数据入库；数据库卷不入库 |
| 用户上传数据 | `vec_db_user` | 本地演示的「用户数据集」空间 | 否 |
| 测试首跑库 | `vec_db_test` | 真实构建链路/权限守卫的首次验证 | 否 |
| 企业租户 | `vec_db_ent_<id>` | 每个企业独立物理库 | 否 |
| 账号/会话 | `rag_auth` | 企业、账号、会话、上传归属 | 否 |

> 「按企业分库」不是在一个库里加 `tenant_id`。它让不同企业的向量表、BM25 索引、
> 上传归属在连接层就分开；代价是建库/迁移要按企业逐个执行，换真实多租户前需要接
> 数据库编排（见 [部署指南](部署指南.md)）。

## 2. 画像表 `user_profile_vectors`

一行 = 一个用户画像样本。demo 库当前 8,110 行（由 21,000 条交易记录聚合而来）。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `SERIAL` | 代理主键 |
| `user_id` | `VARCHAR(50)` | 画像 ID；**demo 中不是稳定实体键**，见 README「数据口径」 |
| `profile_text` | `TEXT` | 用于检索的画像文本（属性 + 行为 + 偏好摘要） |
| `embedding` | `vector(1024)` | BGE-M3 稠密向量 |
| `dept` | `VARCHAR(50)` | 归属部门/业务域，用于过滤 |
| `sensitivity` | `INT` | 敏感级别，默认 1 |
| `update_time` | `TIMESTAMP` | 最近更新时间 |
| `metadata` | `JSONB` | 扩展元数据（来源、批次、原始字段等） |
| `age` / `gender` | `INT` / `VARCHAR(16)` | 结构化画像属性 |
| `city` | `VARCHAR(64)` | 城市 |
| `member_level` | `VARCHAR(32)` | 会员等级（普通/白银/黄金/钻石） |
| `order_count` | `INT` | 购买记录行数（demo 无订单号，不能等同订单数） |
| `total_amount` | `NUMERIC` | 累计消费金额 |
| `avg_amount` | `NUMERIC` | 平均客单价 = `total_amount / order_count` |
| `top_category` | `VARCHAR(64)` | 金额最高的偏好品类 |
| `days_since_last_buy` | `INT` | 距最近一次购买的近似天数（2024 历史快照口径） |
| `platforms` | `VARCHAR(200)` | 来源平台（天猫/淘宝/京东/拼多多/苏宁/1688 等） |

索引：

- `embedding`：HNSW + `vector_cosine_ops`（`user_profile_vectors_embedding_idx`）
- `city`、`member_level`：普通 B-tree，服务 Text2SQL 条件过滤

## 3. 文档表 `wiki_vectors`

Markdown 业务知识库（SOP、会员权益、标签口径、营销手册等）的分块表。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `SERIAL` | 代理主键 |
| `doc_name` | `VARCHAR(100)` | 文档名，用于来源展示与去重 |
| `chunk_text` | `TEXT` | 文档分块正文 |
| `embedding` | `vector(1024)` | BGE-M3 稠密向量 |
| `dept` / `sensitivity` | — | 与画像表同义 |
| `metadata` | `JSONB` | 章节、父块、切分策略等 |
| `update_time` | `TIMESTAMP` | 更新时间 |

- 检索命中 chunk 后按父块回退，减少长文档上下文碎片化。
- 返回结果时以 `doc_name` + 片段映射回来源。

## 4. 混合检索索引表 `search_index`

BM25 分词结果与 BGE-M3 稀疏权重落库，避免每次检索重新计算/常驻内存。

| 字段 | 类型 | 说明 |
|---|---|---|
| `corpus_id` | `VARCHAR(64) PK` | 画像/文档 chunk 的统一语料 ID |
| `source` | `VARCHAR(128)` | `user_profile` / `wiki` 等来源 |
| `text` | `TEXT` | 原文，用于 BM25 打分与引用 |
| `bm25_tokens` | `TEXT[]` | 中文分词后的 BM25 tokens |
| `sparse_weights` | `sparsevec(250002)` | BGE-M3 稀疏向量（词表维度） |
| `updated_at` | `TIMESTAMP` | 更新时间 |

配套 `search_index_meta` 键值表保存**语料指纹**（画像/文档哈希），用于判断
「索引是否落后于源表」。导入或修改源数据后必须重跑 `build_search_index.py`，
否则检索会静默使用旧索引。

## 5. 账号、企业与会话（`rag_auth`）

| 表 | 关键字段 | 用途 |
|---|---|---|
| `enterprise` | `id`, `name`, `invite_code`, `dataset` | 企业租户；`dataset` 指向该企业物理库 |
| `app_user` | `username`, `contact`, `password_hash`, `account_type`, `role`, `enterprise_id`, `status`, `is_*_admin` | 账号体系；密码使用 Argon2 哈希 |
| `session` | `token_hash`, `user_id`, `expires_at` | Cookie 会话；只存 token 哈希 |
| `upload_owner` | `upload_id`, `enterprise_id`, `user_id` | 上传批次归属，防止拿到 upload_id 越权构建/查询 |

角色与能力（L1~L4 + guest）不写死在业务逻辑里，而是持久化到
`var/permissions.json`（路径可用 `RAG_PERMISSIONS_PATH` 覆盖）；详见 README 的权限章节。

## 6. 数据不变量

1. **demo 是评测基线**：`demo` 库不能被用户上传覆盖，否则 `run_eval.py` 不可复现。
2. **派生索引可重建**：`search_index` 与 `search_index_meta` 随时可由画像/文档表重建。
3. **画像表按 user_id 去重聚合**：demo 的 `user_id` 是随机抽样 ID，不可当真实实体；
   接真实订单数据时需先做实体消解（entity resolution），否则「用户累计」仍会冲突。
4. **敏感信息**：手机号/身份证号只以脱敏形式进入回答；原始上传文件在 `data/uploads/`，
   属运行期数据，已被 `.gitignore` 排除。
