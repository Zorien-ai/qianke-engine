# M6.2 文档工程化：构建、路由、死链与状态检查

> 目标：把 Handbook 的发布门禁从人工检查推进为可重复执行的 CI 检查  
> 状态：本地脚本 + GitHub Actions workflow 已落地；远端 CI 尚未实际运行

## 1. 新增文件

- `docs-site/scripts/check-content.mjs`
- `.github/workflows/handbook-docs.yml`

## 2. 检查范围

```text
1. 公开文章数：6 × 10 = 60；
2. 每篇 frontmatter 必填字段；
3. 每篇 12 个二级章节（忽略代码围栏内标题）；
4. 禁止旧错误码 READ_ONLY_VIOLATION 出现在公开文章；
5. V0.5.2 基线存在，V0.5.1 历史文件保留但不进入公开清单；
6. 相对 Markdown 链接目标存在；
7. docs-site 指向 V0.5.2 且排除 V0.5.1；
8. 构建产物中 60 个文章页面存在；
9. VitePress 构建自身的 dead link 检查。
```

## 3. 本地验证

```text
cd docs-site
npm run build
node scripts/check-content.mjs --require-dist
```

结果：

```text
handbook content check: 60 articles, 0 errors, 1 warning
warning: V0.5.1 历史文件存在，已从公开清单排除
handbook content check: PASS
```

## 4. CI

`.github/workflows/handbook-docs.yml`：

```text
触发：push / PR 修改 docs/handbook/** 或 docs-site/**
步骤：checkout → Node 22 → npm install → npm run build → check-content --require-dist
```

## 5. 边界

```text
- GitHub Actions 尚未在远端实际运行；
- 本地只验证了脚本和构建，不等于 CI 已通过；
- 当前未接入自动部署，也未校验外部链接；
- 后续可增加：外部链接检查、发布前路由 smoke、内容 SHA 基线校验。
```
