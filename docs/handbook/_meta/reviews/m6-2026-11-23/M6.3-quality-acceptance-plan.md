## 1. 为什么不与 M6.1/M6.2 混跑

```text
内容修复只改文档，不应伪造全量业务测试结果；
全量测试/Eval 需要模型 Key、PostgreSQL、外部服务与更长运行时间；
生产并发/SLO 需要部署环境和监控数据；
混跑会让“文档修复通过”被误读成“生产质量已验证”。
```

## 4. 验收标准

```text
pytest：全部通过，skip 需列原因；
Regression：不低于冻结基线，失败项需分诊；
Benchmark：报告完整，不能把 development set 结果外推为生产成功率；
并发：达到约定并发与错误率阈值，记录 p50/p95/p99；
SLO：按已定义 SLI/目标验证，未定义目标不得声称达标。
```

## 5. 证据归档

```text
- pytest 输出日志
- Regression/Benchmark JSON + Markdown 报告
- 压测脚本、参数、原始结果与截图
- Prometheus/Grafana 查询与时间窗口
- 失败项分诊记录
```
