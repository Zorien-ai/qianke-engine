# 千客 B 端 2.0 · P0 离线设计稿说明

## 2. 信息架构与页面框架

桌面使用固定左导航、顶部店铺信息、内容区；手机使用顶部菜单、四项底部快捷入口和单列内容。导航按工作目的分组：

| 分组 | 入口 | 原型内容 |
| --- | --- | --- |
| 工作台 | 工作首页 | 随店主、客服、仓库视角变化 |
| 交易与商品 | 订单管理、商品与 SKU | 列表、详情、选择和操作预览 |
| 客户服务 | 客服会话、售后处理 | 会话布局；售后为标明“规划”的说明页 |
| 经营与管理 | 经营报告、权限与审计 | 标明“规划”的能力边界说明，不生成假报告 |

正式实现还须保留基线中的超级运营员、策略治理、审计、用户画像、售后等已授权能力。本稿没有逐页重画这些模块，不意味着可以删除原有入口或接口；应按前序信息架构与实际权限归组。

顶部持续显示店名、单店模式及“模拟交易”。切店按钮禁用，并解释商家成员关系尚未接入；手机保留单店说明，不展示可操作的假切换器。角色显示在桌面头像标记及演练控件中。

内容区统一顺序：页面名称与任务说明 → 关键汇总或筛选 → 工作列表 → 必要口径说明。样例数量明确来自本稿的完整固定集合，不把已加载分页条数当作全店汇总。

## 3. 三类角色首页

| 视角 | 首要内容 | 下一步 | 限制 |
| --- | --- | --- | --- |
| 店主 | 今日模拟完成流水、模拟完成订单、待发货样例 | 待发货、低库存、待模拟支付；查看完成明细 | 无真实收款、利润、同比或环比结论 |
| 客服 | 顾客对话与关联订单上下文 | 查看订单、售后入口 | 对话为虚构；输入和发送禁用；不伪造未读、分配或在线状态 |
| 仓库 | 低库存 SKU、待发货、商品与规格数量 | 核对可用/锁定/安全量，进入商品工作区 | 不预测销量或采购周期；批量保存待接入 |

三个业务视角是设计提案，不能直接等同于当前服务端的 `owner/admin/staff` 角色。正式版应使用已确认的权限映射决定默认入口、可见数据及可执行动作，并由服务端执行授权。原型让店主演练模拟支付/完成，让客服仅查阅，让店主与仓库预览库存和发货，不构成已生效的权限契约。

客服是否复用现有 CApp/IM 后端仍待确认。原型只表达 B 端坐席布局，不将店宠人格作为客服主界面，也不声称已实现坐席收件箱、分配或实时消息。

## 4. 订单列表、详情和模拟动作

### 4.1 列表与筛选

固定 8 笔样例，每页 4 笔。状态标签为全部、待模拟支付、待发货、已发货、已完成。支持按订单号、顾客或商品名查询；输入后点击“查找样例”。桌面表格展示订单/商品、顾客、模拟金额、状态和详情；手机改成卡片，保留同一组重要信息和复选框。

选择有两层：选择本页，以及明确的“选择当前筛选全部 N 笔（含其他页）”。翻页保留选择；改变筛选、角色或导航清空选择，避免把旧范围带入新上下文。批量栏展示数量和范围语义。

正式版的跨页全选不能只依赖前端缓存，应确定服务端筛选快照或查询标识、店铺、选择总量、排除 ID、失效时间及执行前复核机制。本稿只演示固定 8 笔样例全集的选择行为。

### 4.2 订单详情

桌面为 570px 右侧抽屉，手机为全屏详情。头部是订单号与店铺；主体按状态/金额、交易说明、顾客与时间、商品明细、履约信息、状态记录展开；底部保留关闭及当前允许动作。状态变化记录明确标为原型演练。

不展示伪造地址或物流单号。详情明确区分创建时间与完成时间，并显示 DEMO 来源。真实数据接入后，应沿用订单与顾客数据最小可见权限。

### 4.3 二次确认

仅店主预览下开放两种页面内演练：

| 前置状态 | 按钮 | 确认内容 | 页面内结果 |
| --- | --- | --- | --- |
| CREATED | 模拟支付（演示） | 示例店、订单号、金额、操作者、前后状态、无真实收款提示 | 更新为待发货，不增加完成流水 |
| SHIPPED | 模拟完成（演示） | 同上，并确认北京时间的完成时间 | 更新为已完成，加入对应完成日期的样例统计 |

确认按钮使用“仅更新原型样例”；返回不改变状态。日期仅允许固定演练日期 2026-11-13。所有变化只存在本页内存中，刷新或重置恢复。没有资金、库存、物流或服务端写入。

正式实现应按决策文档补齐 `is_simulated`、支付/完成来源、时间戳及服务端审计。审计至少包括操作者、角色、店铺、订单、动作、金额、前后状态、原因和请求标识。原型时间线不是服务端审计系统。

### 4.4 批量发货与导出

原型会预览选中订单中的可发货范围与排除原因。初始全选 8 笔：3 笔待发货可进入预览，另外 5 笔因状态不符被排除。真正提交保持禁用，避免将预览成功当作发货成功。

CSV 下载实际导出当前选择的虚构订单，并逐条附带样例声明。客服视角导出禁用。该文件是本机同步样例导出，不是已落地的生产异步导出能力。正式导出还需要权限、字段脱敏、服务端选择范围、任务进度、文件有效期及下载审计。

## 5. 商品、SKU 与库存预览

3 款商品共 6 个 SKU。商品卡表达名称、规格数及库存合计；SKU 行分别显示可用、锁定、安全库存和价格。图片是内联示意图标，不代表已有商品素材。现有商品图片管理能力应继续保留，本稿没有重新设计上传流程。

低库存规则仅用于样例：`可用量 ≤ 安全量`；显示差额 `max(0, 安全量 − 可用量)`。初始低库存 3 项。差额不是经销量预测或采购周期推算的补货建议。

勾选多个 SKU 后出现批量栏；预览按 SKU 实物总量填写，并保留锁定量。示意公式为 `预览可用量 = 盘点实物量 − 锁定量`。输入必须为整数且不小于锁定量；错误就近显示，保存始终禁用。正式库存字段、并发版本和锁定语义仍需后端确认。

本稿的 6 个 SKU 在同一页，未演示 SKU 跨页选择。生产版跨页批量改库存仍需与订单一样明确选择快照、权限和结果契约；每个 SKU 应返回独立成功/失败原因，处理并发变化并写审计，不能只弹出整批成功提示。

## 6. 状态、组件与可访问性

| 状态 | 显示 | 恢复方式 |
| --- | --- | --- |
| 正常 | 当前角色与页面的固定样例 | 正常导航 |
| 加载中 | 保留页面标题、骨架和说明，不显示伪造的 0 | 演练控件切回正常 |
| 空数据 | 解释当前店铺/筛选范围无记录，不推断全店无业务 | 清除筛选演练 |
| 加载失败 | 明确没有取得数据，不复用空数据文案 | 重试演练 |
| 权限不足 | 说明角色无权限并提示联系店主 | 返回当前角色首页 |
| 能力待接入 | 展示依赖说明，提交或发送禁用 | 等待正式接口接入；原型不伪造成功 |

组件：分组导航、店铺栏、模拟环境标识、KPI 卡、任务行、订单筛选、订单表/卡、跨页选择提示、批量栏、商品/SKU 卡、详情抽屉、确认弹窗、状态面板与轻提示。

表单有可读标签；按钮使用明确动作名称；采用原生 `dialog`，有关闭与返回按钮；焦点轮廓可见。手机收起的侧栏使用 `visibility:hidden`，不留在键盘和可访问性树中；展开后恢复。支持 Escape 收起导航，骨架动画尊重减少动态效果偏好。本次没有完成完整读屏或 WCAG 审计。

## 7. 字色与响应式规则

| 项目 | 设计值 |
| --- | --- |
| 页面底色 | `#f5f6f2` |
| 卡片纸面 | `#ffffff` |
| 正文 | `#253d3b` |
| 次级文字 | `#657b77` |
| 边界 | `#dbe3df` |
| 主强调 | `#24675f` |
| 选中浅底 | `#e0eee8` |
| 正文与关键业务行 | 18px |
| 辅助文字、紧凑控件下限 | 16px，不以缩到 13/14px 换取密度 |
| 标题与金额 | 标题约 22–32px，重点金额约 28–38px |
| 卡片圆角 | 14px，层级通过边界、间距与留白区分 |

6:3:1 是视觉分配原则：约 60% 中性纸面、30% 灰青文字/边界/次级面、10% 强调操作。成功、警告和风险色只表达语义，不做装饰性铺满；它不是像素面积测量结果。

- **1440px 桌面**：228px 左侧栏，内容外边距 32px；经营首页三张 KPI、双列任务/报告区；商品三列；订单表格；详情右侧抽屉。
- **768–1150px 中间宽度**：侧栏 200px；内容间距收紧，首页工作区单列，商品两列。该区间有 CSS 规则，本次未逐尺寸验收。
- **390px 手机验收视口**：左栏收起为菜单；首页主金额独占一行，两个次要指标并排；订单表格变卡片，商品单列，客服列表与会话纵向排列；底部首页/订单/商品/客服四入口；批量栏位于底部导航上方，详情占满可用屏幕。

屏幕变窄时优先换行、纵向排列、折叠次要结构，不缩小业务正文。商品与详情保留字段含义，不依赖单独颜色判断状态。

## 8. 与基线的设计差异及接入顺序

以下是对已读取基线的建议，不能当作同行正在开发版本的缺陷清单。

| 基线情况 | 本稿建议 | 实施注意 |
| --- | --- | --- |
| 以订单等模块直接进入工作 | 增加按角色组织的任务首页和分组导航 | 保留原能力；默认入口由真实权限决定 |
| 支付/完成动作使用一般业务措辞 | 全程显示模拟交易，二次确认影响范围 | 不改后端状态机语义来配合视觉文案 |
| 订单列表与操作密集 | 桌面表格+详情抽屉，手机卡片+全屏详情 | 保留原始订单标识及当前筛选上下文 |
| 商品数据以现有单条接口为主 | 商品与 SKU 层次分开，增加选择及差异预览 | 接口未落地前禁用提交，不循环单条接口冒充可靠批量能力 |
| 尚无确认的多店与完整坐席能力 | 单店禁用状态、坐席布局说明 | 先明确身份/成员关系及会话契约 |
| 模拟订单缺少可靠完成统计契约 | 页面明确完成时间口径及来源 | 不拿当前加载的记录或创建时间替代全店完成汇总 |

建议对照时先确认壳层、字号、模拟标识和角色首页，再复用订单/商品组件，最后按后端契约接入多店、会话、批量与经营报告。本稿已经画出的交互不等于对应能力已经实现或获准上线。

## 9. 仍需后续决定的事项

1. 客服是否复用 CApp/IM，坐席分配、未读及身份如何定义。
2. 多店需求采用同一账号多商家成员关系，还是其他身份模型；服务端切店后的上下文失效规则。
3. 完成口径下退款、取消、跨月完成如何冲减或归属。
4. 批量选择快照、部分失败、幂等、库存并发控制与重试策略。
5. 导出是否异步，以及文件有效期、敏感字段权限与审计要求。
6. 店主/客服/仓库业务视角与现有服务端角色的映射。

这些依赖不阻塞本次设计评审；原型已用禁用、规划或明确的页面内演练表达边界。

## 10. 实际验收与限制

验收环境：Windows Edge，本地只读 HTTP 预览，桌面视口 1440×1000、手机响应式视口 390×844。固定演练日期 2026-11-13，时间字段标为北京时间。手机是浏览器视口测试，不是实体手机测试。

| 验收项 | 实际结果 |
| --- | --- |
| 店主、客服、仓库首页 | 分别呈现经营、对话、商品库存重点；客服发送禁用 |
| 多店边界 | 切店禁用，单店说明可见 |
| 订单跨页选择 | 8 笔全选，翻到第 5–8 笔仍保留 8；切换筛选清空选择 |
| 批量发货预览 | 初始 3 笔可处理、5 笔因状态排除；正式提交禁用 |
| 实际 CSV 文件 | 浏览器产生 8 行数据、8 个唯一订单、9 列；逐行含虚构样例声明 |
| 模拟支付 | 返回后仍待模拟支付；确认后变待发货，仅页面内存更新 |
| 模拟完成 | 非演练日期被拒；11 月 13 日 11:30 可完成；首页 484+296=780，完成订单 3→4 |
| 重置 | 恢复 484 元、3 笔已完成及 3 笔待发货 |
| 客服订单动作 | 待模拟支付订单详情只提供查看/关闭，不开放模拟支付 |
| 库存预览 | LJ100 锁定 2，输入 1 显示错误；输入 20 得可用 18、差额 +10；保存禁用 |
| 四种异常状态 | 加载、空数据、失败、权限不足可切换；重试恢复页面，权限不足返回角色首页 |
| 手机布局 | 卡片、全屏详情、库存弹窗、客服布局和底部导航可用；批量栏未覆盖底部导航；关闭侧栏退出可访问性树 |
| 字号与溢出 | 业务 SKU 行 18px、辅助文字 16px；1440/390 视口下文档宽分别为 1425/375（Windows 垂直滚动条占位），未见文档横向溢出 |
| 浏览器错误 | 本次可取得的错误日志为空；不等于完整兼容性审计 |
| 静态检查 | 内联 JavaScript 语法检查；无外部资源或网络 API 调用；变更范围核对 |

下载事件等待工具未返回结果，但实际文件已在本机 Downloads 中生成，以上导出结果由文件解析核实，不以页面提示替代下载证明。

`file://` 打开被浏览器工具的协议安全策略阻止；没有绕过策略，也不声称已实测双击运行。单文件结构与无外部依赖已检查，本地 HTTP 交互已实际验收。Safari、实体手机、中间断点、完整辅助技术操作及生产接口未测试。

本次没有改 Agent 核心逻辑，因此未运行生产 `pytest`、Regression Eval 或 Benchmark Eval；不把离线原型检查算作生产验收。
