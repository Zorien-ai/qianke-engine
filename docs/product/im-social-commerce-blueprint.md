# 千客引擎：IM 社交电商 Agent 蓝图

**版本：** v0.1  
**状态：** 产品愿景 / 架构约束，不等同于当前已实现能力  
**关联决策：** `docs/decisions/three_agent_platform_architecture_decisions_v0.1.md`

---

## 1. 产品定位

千客引擎不是传统商城，也不是单纯问答机器人，而是：

```text
以 IM 为载体
以 Agent 为代理
以可配置的“伙伴/宠物形象”为情感界面
以真实交易与商家服务为闭环
的社交电商 Agent 平台
```

三个关键词：

- **IM 优先**：好友、会话、@ 唤醒，而不是纯搜索框。
- **Agent 代理**：用户和商家各自拥有自己的 Agent，代理意图、查询和谈判。
- **可配置伙伴**：宠物只是表现层，不是硬编码“锦鲤”；可以是鱼、猫、机器人、品牌吉祥物。

## 2. 三端角色

### C 端：用户与伙伴

- 用户拥有一个可配置的伙伴 Agent（名称、形象、语气可配置）
- 伙伴负责：推荐、预算、订单准备、提醒、与好友/店宠互动
- 消费、签到、互动可以提升伙伴的成长值/饱食度
- 伙伴不能代替用户确认订单

### B 端：商家与店宠

- 商家作为特殊好友存在，可被用户添加
- 店宠 Agent 绑定商家知识库、商品库、SOP 和促销规则
- 只有被 `@` 唤醒且命中意图白名单时才响应
- 越界闲聊、未授权话题不进入大模型
- 店宠只能在授权范围内报价和发券，不能直接扣款

### A 端：平台管理

- Agent 存活状态、Token 成本、Trace、审计
- 高危操作拦截
- 不直接干预具体交易
- 不直接连接商户业务库

## 3. “伙伴”抽象

“锦鲤”只是第一版表现，不是产品模型。

统一抽象：

```text
Companion
├── owner_id
├── name
├── species        # fish / cat / robot / brand_mascot / custom
├── persona        # 语气、称呼、行为风格
├── level
├── satiety / exp
└── appearance     # 前端可换的视觉资源
```

原则：

- 后端只存抽象字段，不把“鱼”写死进业务逻辑
- 前端根据 `species`/`appearance` 渲染不同形象
- 商家也可以有“店宠”，但 Agent 权限与 C 端伙伴完全不同
- 宠物养成是激励层，不是权限层

## 4. 双宠谈判机制

“双宠谈判”不是把一个 Multi-Agent Graph 塞进一个请求，而是：

```text
C 用户 Agent（守护伙伴）
        │  @店宠 + 用户意图
        ▼
B 商家 Agent（店宠）
        │  唤醒校验 + 意图白名单
        │  SQL 查用户画像 / RAG 查商家规则
        ▼
给出报价/优惠建议
        ▼
用户明确确认
        ▼
创建模拟/真实订单
```

工程边界：

1. C 和 B 是两个独立 Agent Graph，各自有权限、预算和 Trace。
2. B 端 Agent 只响应 `@店宠`，且只处理白名单意图。
3. 越界闲聊固定话术拦截，不调用 LLM。
4. 任何价格、优惠、订单动作必须可追溯到工具结果。
5. 订单创建必须用户确认，Agent 不能自行完成资金操作。
6. A 端只审计，不参与谈判。

## 5. 技术底盘

```text
单 Agent ReAct 编排
├── rag_search
├── execute_sql（只读）
└── calculator
```

不让 LLM 直接写库。

关键防线：

- SQL 只读账号 + 正则/白名单 + LIMIT
- Tool 级授权 + 执行时复核
- B 端 `@` 唤醒 + 意图白名单
- 请求幂等 + 租户隔离
- Budget / Timeout / Checkpointer
- HITL 确认 + 审计
- LangSmith / Eval 回归

## 6. 演进路线

| 阶段 | 内容 | 当前状态 |
|---|---|---|
| 一 | B 端单体 Agent + 3 Tool + 安全校验 | 已有基础，持续稳定化 |
| 二 | C 端购物 + 模拟订单 + HITL | Mock 闭环已跑通 |
| 三 | IM 社交壳、好友、会话、可配置伙伴 | 进行中 |
| 四 | 双宠谈判、商家入驻、店宠 | 待开发 |
| 五 | 真实支付/IM 协议/SaaS 交付 | 待开发 |

阶段三不应跳过：

```text
没有 IM 会话和伙伴抽象
就不要直接做“双宠谈判”
```

## 7. 成功指标

### 产品

- 用户完成一次推荐→确认→订单的转化率
- 好友会话活跃度
- 伙伴互动/养成留存
- 店宠响应率与用户满意度

### 安全

- 未授权 Tool 调用拦截率 100%
- 跨租户访问 0
- 未确认订单创建 0
- 越界意图进入 LLM 的比例可控

### 工程

- Eval Regression 不退化
- P95 延迟、Token/任务成本可观测
- 每个 Agent 执行有 Trace、有状态、可恢复

## 8. 非目标

第一版不做：

- 真实资金自动执行
- 无确认的自动下单
- 全自动多 Agent 自由博弈
- 复杂 Memory 自动演化
- 大规模微服务拆分

## 9. 一句话

> 用“伙伴/宠物”的情感外壳降低 Agent 的理解成本，  
> 用“单 Agent + 确定性工具 + 人工确认”的工程底盘保证交易安全。
