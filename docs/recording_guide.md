# 千客引擎 · 录屏操作指南

> 对应脚本：[`docs/video_script.md`](video_script.md)
> 目标：用**真实 Vue 前端**录出「上传 → 构建 → 对话 → 增量更新 → 知识库」的顺滑素材，后期再配你的 AI 声音。
> 建议录 5 段独立素材，不要一镜到底卡时间：A 痛点（外部表格）、B 首页/产品、C 导入构建、D 对话、E 增量 + 知识库 + 结尾。

### 数据准备：用仓库自带的「示例数据」

这些文件已入库，不需要手工造：

| 用途 | 路径 | 内容 |
|---|---|---|
| 首次全量构建 | `data/dianshuang/` | 6 个平台 CSV（各 1,000 行，共 6,000 行）+ `data/docs/` 6 篇规则文档 |
| 增量更新 | `data/new-dianshuang/` | 6 个平台 CSV，共 **2,000 行**新订单，带 `数据批次` 列（模拟新数据，不覆盖原数据） |
| 画像/文档规则 | `data/docs/` | `tag_definitions.md`、`marketing_playbook.md`、`cs_sop.md`、`member_benefits.md`、`segmentation.md`、`analysis_report_template.md` |

首次全量：

1. 登录 `admin`，打开 `http://127.0.0.1:8000/v2/#/setup`；
2. 点 **「用示例数据填满」**（按钮在第 1 步底部）——等价于把 `data/dianshuang` 6 个 CSV + `data/docs` 6 篇文档放进上传批次；
3. 点 **「下一步：确认字段 →」**，确认 `用户ID → user_id` 等字段被识别；
4. 点 **「下一步：开始构建 →」**；
5. 首次没有构建基线，第 3 步的「追加更新」会显示**不可用**，选 **「覆盖重建」**，点 **「开始构建」**，弹窗点 **「确认覆盖重建」**；
6. 构建完成后进入 `/v2/#/kb`，确认「知识库概况」显示数据集 `test`、文档/切片/画像数、状态「已构建」、数据状态「已就绪」。

> 首次全量构建时间取决于机器和数据量，开发机上是**分钟级**（不是「三分钟」精确值）。
> 录「构建进度」镜头时正常录，后期 2–4× 加速；如果不想等，可以**先预构建一次**，只录后面的步骤，构建进度用一小段小文件构建来补拍。

### 增量更新准备

1. 复制新数据到独立目录（不要改原目录）：
   ```powershell
   New-Item -ItemType Directory data\recording -Force
   Copy-Item data\new-dianshuang\*.csv data\recording\
   ```
2. 回到 `/v2/#/setup`（上传批次会自动恢复）；
3. 把 `data/recording` 里的 6 个 CSV 拖进 **「交易数据」** 区域（或点击区域选文件）；
4. 下一步 → 确认字段 → 构建页，系统会显示 **「追加更新（推荐）」**，并显示「新增 CSV 6 个 / 已有 4,400 用户不受影响」；
5. 点 **「开始构建」**，无需二次确认；
6. 完成后到 `/v2/#/kb` 刷新，展示概况与「已就绪」。

> ⚠️ 脚本里「新增了一万条 / 几秒钟」与实际示例数据不一致：`data/new-dianshuang` 是 **2,000 行**，增量构建通常快于全量但不是固定「几秒」。
> 建议把口播改成「新增了一批数据 / 很快就同步完成」，或者准备真实 10,000 行数据再按脚本说。录屏加速时加一个「演示加速」小角标，避免宣传失实。

### 「脏数据 CSV」怎么做

不要为了画面故意做**无法解析的坏文件**（后端会拒绝或字段识别失败，录屏会翻车）。推荐用**结构不干净但可解析**的文件：

- 直接用 `data/new-dianshuang/天猫.csv`：比原始数据多一列 `数据批次`，看起来「乱」但能正常识别；
- 或复制 `data/dianshuang/天猫.csv` 到 `data/recording/` 后加一列 `备注`（全空即可），证明系统能忽略无关列；
- 录之前先在浏览器里试传一次，确认「交易文件 N 个 / 行数」出现且能进入第 2 步。

## 1. 录屏前的机器与浏览器设置

- 分辨率：**1920×1080 / 60fps**；浏览器窗口全屏（F11），缩放 **100%**；
- 使用干净的 Chrome 用户资料：隐藏书签栏、扩展、通知；关闭微信/QQ/邮件弹窗；
- 主题：工作台用浅色（默认），首页 Hero 是暗色；不要中途切主题；
- 录制格式：OBS/显卡录制 60fps、CQP 18–20、音频先录静音或只录系统提示音；配音后期加；
- 鼠标：点击前停 0.3–0.5s；点击后手离开鼠标 0.5s；不要来回晃；
- 录前预热：先打开一次 `/v2/#/chat` 让前端资源加载，刷新回首页开始录；**不要提前问脚本里的问题**（否则会命中缓存，失去流式感）；
- 关闭 Safari/Edge 的“翻译此页”、Grammarly、密码管理器自动填充弹窗；
- 录屏前把测试数据准备好、页面登录好，避免录到登录/加载等待。

> 建议用独立浏览器窗口 + 系统级屏幕录制，录完再裁剪浏览器边框；若用浏览器插件录制，确认输出是真 60fps，不是 30fps 补帧。

## 2. 分镜操作卡（按脚本时间）

### 0:00–0:10 痛点开场（不需要录产品）

| 步骤 | 操作 |
|---|---|
| 1 | 打开 `data/dianshuang/天猫.csv`（Excel/表格软件），缩放到列名和数字清晰；截图或录 3–5s 缓慢推近 |
| 2 | 后期在画面上叠「需求排期：等待中…」红卡和进度点；不要真的去点公司工单系统 |
| 3 | 0:07 后画面失焦/切黑；音乐先入 0.5s |

### 0:10–0:20 首页 → 工作台

| 步骤 | 操作 |
|---|---|
| 1 | 浏览器打开 `http://127.0.0.1:8000/v2/#/home`，已登录状态 |
| 2 | 等 2–3s，让星云和「千客引擎」Logo 稳定（Hero 的完整故事 8.2s，不要等它全部跑完） |
| 3 | 鼠标移到右上角或 Hero 主按钮 **「进入工作台」**（未登录窗口才是「免费体验 Demo」） |
| 4 | 点击，等 0.8–1.2s，让工作台（默认 Dashboard）完全出现 |
| 5 | 停止录制本段；后期加 0.25s 暗场/白场转场 |

### 0:20–0:35 数据导入（setup）

| 步骤 | 操作 |
|---|---|
| 1 | 地址栏 `#/setup`，或从侧边栏 **「数据导入」** 进入 |
| 2 | 停 0.5s 展示「上传数据」页；点 **「用示例数据填满」**（推荐，避免文件选择器打断录屏） |
| 3 | 等文件列表出现：6 个交易文件、6 篇规则文档、总行数、`6/6 字段自动识别`；给这个摘要一个 1.5s 特写 |
| 4 | 点 **「下一步：确认字段 →」**；停 1s，展示 `用户ID → user_id` 等映射 |
| 5 | 点 **「下一步：开始构建 →」**；首次构建选 **「覆盖重建」**；点 **「开始构建」** → 弹窗 **「确认覆盖重建」** |
| 6 | 录进度：第 3 步的 4 个步骤（清洗/聚合/向量化/索引）和百分比；完成后停 0.5s |
| 7 | 若后面要直接录对话，可点 **「下一步：提问验证 →」** 或直接切到侧边栏「对话」 |

### 0:35–0:50 对话与溯源（chat）

| 步骤 | 操作 |
|---|---|
| 1 | 侧边栏 **「对话」** 或地址 `#/chat`；停 0.5s 展示空态 |
| 2 | 点击输入框，**逐字输入**（不要粘贴）：`最近一次购买超过30天的美妆高客单女性用户有哪些？给一个挽回方案。` |
| 3 | 点 **「提问」**；让「检索中 → 生成中」状态出现 1–2s |
| 4 | 回答流式出现时，鼠标不要滚太快；等结论、表格、`[来源N]` 出现后，缓慢下移到「数据来源」 |
| 5 | 点 **「展开过程」**，展示来源列表：`user_profile`（画像）、`marketing_playbook.md`、`cs_sop.md`、`tag_definitions.md` 等；鼠标在来源标签上停 1s |
| 6 | 如果画面需要「画像卡片」，插 0.5–1s 官网 Hero 的真实 demo 画像卡作 B-roll；不要把对话页的来源列表硬说成卡片墙 |

> 为什么改问「最近一次购买超过 30 天」：演示数据有 `最近购买时间`/`days_since_last_buy`，没有「最近消费下降」的时间序列；
> 原句可能被模型判为数据不足。录前先试问原句，若出现「数据不足」，用上面的 fallback。
> 参考问题在 demo 库实测能答出「画像 + SOP」来源；在 `test` 全量构建完成后请**先预问一次**，确认你的数据空间里也能稳定返回来源，再正式录。

### 0:50–1:05 增量更新 + 知识库

| 步骤 | 操作 |
|---|---|
| 1 | 回 `#/setup`；上传批次应自动恢复（页面提示「已恢复上次的上传」） |
| 2 | 把 `data/recording` 里的 6 个 CSV 拖入 **「交易数据」**；等文件列表更新 |
| 3 | 点 **「下一步：确认字段 →」** → **「下一步：开始构建 →」**；第 3 步应自动/手动选中 **「追加更新」**（推荐），展示「新增 CSV / 已有用户不受影响」 |
| 4 | 点 **「开始构建」**（增量不需要二次确认）；录进度，后期加速 |
| 5 | 切到侧边栏 **「知识库」** `#/kb`；点 **「刷新」**；展示概况 4 张卡、数据状态「已就绪」、文档矩阵 |
| 6 | 97% 与盾牌：UI 里没有这个大盘；后期叠图形层，或切 `tests/eval_report.md` 中的 97% 统计，再回知识库；不要伪造产品页面 |

> 注意：知识库页的按钮叫 **「重建索引」**（覆盖重建），不是「追加更新」。脚本里 0:50 的「追加更新」请务必录 **数据导入向导第 3 步**，不要把知识库页的按钮硬剪成增量。

### 1:05–1:15 结尾 CTA（首页）

| 步骤 | 操作 |
|---|---|
| 1 | 用**未登录的独立窗口**打开 `http://127.0.0.1:8000/v2/#/home`（这样 CTA 是「免费体验 Demo」；已登录会显示「进入工作台」） |
| 2 | 等 Logo/星云稳定，鼠标停在 **「免费体验 Demo」** 上，不要立刻点（避免跳到登录页打断收尾） |
| 3 | 后期在画面中心叠「千客引擎」Logo + Slogan；按钮保持可见 |
| 4 | 结尾停 1.5–2s，最后 0.4s 黑场；音乐最后一拍落点 |

## 3. 页面与按钮速查

| 页面 | 路由 | 关键控件 |
|---|---|---|
| 官网首页 | `/v2/#/home` | 已登录：**进入工作台**；未登录：**免费体验 Demo** |
| 工作台 | `/v2/#/` | 侧边栏「数据导入 / 对话 / 知识库」 |
| 数据导入 | `/v2/#/setup` | **用示例数据填满** → **下一步：确认字段 →** → **下一步：开始构建 →** → **开始构建** → **确认覆盖重建**（首次） → **下一步：提问验证 →** |
| 对话 | `/v2/#/chat` | 输入框（textarea）→ **提问**；答后 **展开过程** / **收起过程**；**新对话** |
| 知识库 | `/v2/#/kb` | **刷新**、**重建索引**（覆盖重建）、**确认清空**（输入 `test`） |
| 登录 | `/login` | 账号 / 密码 / 登录 |

### 数据核对与清理

- 查看当前数据空间：`/v2/#/kb` 顶部显示数据集名（应为 `test`）。
- 清空演示库（录完或想重录首次构建时）：
  1. `/v2/#/kb` → 底部「清空当前数据空间（不可恢复）」；
  2. 输入 **`test`**；
  3. 点 **「确认清空」**。
  > 千万不要清空 `demo` 或 `ent_32`；`demo` 是评测基线，`ent_32` 是真实企业数据。
- 如要重新录首次构建：清空 `test` 后回 `/v2/#/setup` 重新填示例数据；上传文件会保留，构建记录会重置。

## 5. 可选：控制台 Auto-Pilot

如果不想手动点，可用 [`docs/recording_autopilot.js`](recording_autopilot.js) 在 DevTools Console 里执行：

1. 登录 `admin`，打开 `/v2/#/setup`；
2. F12 → Console，粘贴整段脚本，回车；
3. 执行：
   ```js
   await qkPilot.setupSample()    // 自动：示例数据 → 确认字段 → 开始构建（首次选覆盖重建）
   await qkPilot.ask()            // 自动：跳对话 → 输入问题 → 提问 → 展开来源
   await qkPilot.kb()             // 自动：跳知识库 → 刷新
   ```
4. 或者 `await qkPilot.run()` 一次跑完（构建期间会等待，最长 15 分钟）。

**它能做什么：** 自动点击「用示例数据填满」、下一步、开始构建；自动在对话页输入问题并等流式结束、展开「数据来源」；自动切知识库刷新。

**它不能做什么：** 不能替你在系统文件选择器里选 CSV（所以用「用示例数据填满」）；不能自动上传增量用的 6 个新 CSV（需要真实文件选择器）；不能替代你对镜头/鼠标的审美控制。录正式素材仍建议手动操作，脚本用于排练/对时。

## 6. 已知产品差异（避免剪错）

| 脚本写法 | 实际 UI | 处理 |
|---|---|---|
| 知识库页「追加更新」 | 知识库页只有「重建索引」；追加更新在导入向导第 3 步 | 0:50 录 setup 第 3 步 |
| 画像卡片 | 对话页是「数据来源」列表（画像/文档标签） | 用官网 Hero 画像卡做 B-roll，或后期卡片动效 |
| 97% 大盘 / 盾牌 | 产品 UI 没有该大盘 | 后期图形层或评测报告截图；不伪造 UI |
| 构建「瞬间完成」 | 全量构建分钟级，增量视数据量而定 | 录屏加速 + 角标，或改口播 |
| 新增一万条 | 示例增量是 2,000 行 | 改口播/数据，或不用具体数字 |
