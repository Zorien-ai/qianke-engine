# 接口文档

> 服务实现：`src/rag_demo/api/main.py`（问答 / 认证 / 权限 / 账号）、`src/rag_demo/mvp/app.py`（四步向导）、`src/rag_demo/api/wizard.py`（向导挂载）
> 适用版本：2026-10（M3 登录态 + 四步向导接真）
> 生成方式：按当前代码逐端点核对，字段名与裁剪规则均以代码为准

---

## 1. 概述

### 1.1 服务地址

| 服务 | 启动命令 | 地址 | 说明 |
|---|---|---|---|
| 正式服务 | `uv run uvicorn rag_demo.api.main:app --reload --port 8000` | `http://127.0.0.1:8000` | 问答 + 向导 + 登录 + 管理端 |
| 向导调试服务 | `uv run uvicorn rag_demo.mvp.app:app --port 8002` | `http://127.0.0.1:8002` | 只有向导，**无登录态**，数据集由请求参数决定 |
| 冻结快照 | `uv run uvicorn m1_mock.app:app --port 8001 --app-dir prototype` | `http://127.0.0.1:8001` | M1 内测快照，与本文无关 |

- API 文档（Swagger）：`GET /docs`，`GET /openapi.json`。由 `config.ENABLE_API_DOCS` 控制，生产必须置 `False`。
- 内容类型：除 `/api/wizard/upload` 为 `multipart/form-data`、`/qa/stream` 为 `text/event-stream` 外，均为 `application/json; charset=utf-8`。

### 1.2 前置条件

1. PostgreSQL + pgvector 已启动，且已跑过 `ingest_data.py` / `ingest_docs.py`；
2. 环境变量 `DEEPSEEK_API_KEY` 已设置；
3. 启动时预加载 bge-m3、bge-reranker-v2-m3（约 2GB 显存）与意图分类模型；索引新鲜度检查失败**只告警不阻断**。

### 1.3 鉴权

默认 `AUTH_ENABLED=1`、`RAG_ALLOW_HEADER_AUTH=0`，即**必须登录**：

1. `POST /auth/login` 成功后返回 `Set-Cookie: rag_session=<token>`（`HttpOnly; SameSite=Lax`）；
2. 后续请求带上该 Cookie；
3. 服务端每次请求都把 Cookie 解析成账号，再按账号角色判能力。

请求头 `X-Role` / `X-User` 仅在 `RAG_ALLOW_HEADER_AUTH=1`（且未登录）时生效，属于**演示开关，不是安全边界**。

种子管理员：`admin / admin123`（环境变量 `RAG_ADMIN_USER` / `RAG_ADMIN_PASSWORD` 可改）。

### 1.4 角色与等级

角色由账号决定（`admin` / `ent_admin` / `exec` / `analyst` / `ops` / `cs` / `guest`），等级决定能力：

| 等级 | 默认能力 | 默认角色 |
|---|---|---|
| L1 | `answer` | `cs` |
| L2 | `answer` `sources` `topk` | `analyst` `ops` |
| L3 | L2 + `internals` | `exec` `ent_admin` |
| L4 | L3 + `trace_flow` `sql` `stats` `raw_search` `ops` | `admin` |
| L0 | 无 | `guest`（未识别 / 待审核） |

能力含义：

| 能力 | 含义 | 关联接口 |
|---|---|---|
| `answer` | 提问并拿到回答 | `POST /qa`、`POST /qa/stream` |
| `sources` | 看到来源列表（编号 + 来源名） | `/qa` 响应的 `sources` |
| `topk` | 可调整「返回多少个用户」 | `/qa` 的 `top_k` |
| `internals` | 看到原文片段 / 精排分数 / 检索式 | `sources` 扩展字段、`trace` |
| `trace_flow` | 看到融合与精排汇总 | `trace` 中的 `fused_count` / `limits` 等 |
| `sql` | 看到 SQL 原文与执行报错 | `/qa` 的 `sql` / `sql_error` |
| `stats` | 数据概况与索引新鲜度 | `GET /stats`、`GET /admin/index-status` |
| `raw_search` | 只召回不生成 | `POST /search` |
| `ops` | 运维与权限管理、`dept` 覆盖 | `/admin/*` 中的运维接口、`/qa` 的 `dept` |
| `tenant` | 管本企业成员（身份自带，不受等级影响） | `/admin/users*`（企业管理员） |

等级与能力的映射可在页面上动态修改，落盘 `var/permissions.json`，**改完不用重启**（判定路径每次请求重新读配置）。

### 1.5 状态码约定

| 状态码 | 含义 | 典型 `detail` |
|---|---|---|
| 400 | 参数 / 业务校验失败 | `请先阅读并同意服务条款`、`验证码不正确或已过期，请刷新后重试` |
| 401 | 未登录（前端据此跳登录页） | `请先登录` |
| 403 | 已登录但无权限 / 账号不可用 | `当前身份无权访问该接口`、`账号待审核：请等待管理员通过后再使用`、`该账号已停用` |
| 404 | 资源不存在（上传批次 / 构建任务 / 账号） | `构建任务不存在或已过期...` |
| 409 | 数据集忙（构建或问答持锁中） | `数据集 user 正忙：...` |
| 500 | 环境 / 基础设施失败 | `数据空间准备失败：...` |

错误响应体统一为 FastAPI 默认格式：

```json
{"detail": "当前身份无权访问该接口"}
```

### 1.6 问答响应的按角色裁剪（重要）

`/qa` 与 `/qa/stream` 的返回**不是固定结构**，由 `permissions.render()` 按角色裁剪：无权限的字段会被**整键移除**（不是置空）。各等级可见字段：

| 字段 | L1 | L2 | L3 | L4 |
|---|:--:|:--:|:--:|:--:|
| `route` / `answer` / `cached` | ✓ | ✓ | ✓ | ✓ |
| `sources[].index` / `sources[].source` | ✗ | ✓ | ✓ | ✓ |
| `sources[].text` / `origin_query` / `from_query` / `strategies` / `rerank_score` / `expanded` | ✗ | ✗ | ✓ | ✓ |
| `rows_count` / `sql_rows` | ✓（有 SQL 路时） | ✓ | ✓ | ✓ |
| `sql` / `sql_error` | ✗ | ✗ | ✗ | ✓ |
| `trace` | ✗ | ✗ | ✓（无 flow 汇总） | ✓（全量） |

补充规则：

- `answer` 正文：看不到 `sources` 的角色，正文中的 `[来源N]` 标记会被去掉（`[来源：结构化查询结果]` 这类散文式标注保留）；
- `sql_rows` 最多 20 行，每格截断 60 字（`pipeline.brief_rows`）；
- `sources[].text` 截断 400 字；
- 缓存里存的是**完整结果**，裁剪只发生在发出前，因此角色不进缓存键。

## 2. 页面与探针

### 2.1 GET `/`

返回 `api/static/index.html`。强制登录且未登录时 `302 → /login`。`include_in_schema=False`。

返回 `api/static/login.html`，唯一不需要登录的页面。

### 2.3 GET `/wizard`

返回向导页 `mvp/static/wizard.html`。`AUTH_ENABLED` 且未登录时 `302 → /login`。

- 鉴权：无。不查数据库、不读配置，纯存活探针。
- 响应：

```json
{"status": "ok"}
```

## 3. 身份与认证

### 3.1 GET `/whoami`

前端据此决定渲染哪些控件，权限表不在前端硬编码。

- 鉴权：无（匿名也能调，返回 L0 能力）。
- 请求：无参数（可选 `X-Role` / `X-User`，仅在 `RAG_ALLOW_HEADER_AUTH=1` 时生效）。
- 响应：

```json
{
  "role": "admin",
  "role_label": "系统管理员",
  "user": null,
  "level": "L4",
  "level_label": "L4 全部信息",
  "capabilities": ["answer", "internals", "ops", "raw_search", "sources", "sql", "stats", "topk", "trace_flow"],
  "can": {
    "ask": true, "sources": true, "sql": true, "internals": true,
    "trace_flow": true, "stats": true, "raw_search": true, "ops": true,
    "topk": true, "tenant": false
  },
  "authenticated": true,
  "topk_range": {"min": 1, "max": 30},
  "roles": [
    {"value": "admin", "label": "系统管理员", "usable": true, "level": "L4"},
    {"value": "exec", "label": "管理层", "usable": true, "level": "L3"},
    {"value": "analyst", "label": "数据分析师/产品", "usable": true, "level": "L2"},
    {"value": "ops", "label": "运营/市场", "usable": true, "level": "L2"},

    {"value": "L1", "label": "L1 基础"},
    {"value": "L2", "label": "L2 依据"},

    {"value": "L4", "label": "L4 全部信息"}
  ],
  "account": {
    "id": 1,
    "username": "admin",
    "display_name": "管理员",
    "account_type": "employee",
    "account_type_label": "企业员工",
```

字段说明：

- `account` 仅在登录后出现；`enterprise.invite_code` 只对系统管理员 / 企业管理员返回，其余为 `null`；

- `auth.enforced = AUTH_ENABLED && !ALLOW_HEADER_AUTH`。

### 3.2 GET `/auth/captcha`

发一张 SVG 验证码（base64 data URL，前端可直接塞给 `<img>`）。

- 鉴权：无。
- 响应：

```json
{
  "id": "wJ8xQ2mK7pLd",
  "image": "data:image/svg+xml;base64,PHN2ZyB4bWxucz0i...",
  "expires_in": 300
}
```

- 有效期 300s，**校验一次即作废**（无论对错）；
- 4 位字符，字符集去掉易混淆的 `0/O/1/I`；
- 存内存，单进程；多进程部署需换 Redis。

### 3.3 POST `/auth/register`

开放注册，但一律进**待审核**。

- 鉴权：无。未启用登录时返回 400 `当前未启用登录`。
- 请求体：

```json
{
  "username": "zhangsan",
  "password": "pass1234",
  "contact": "13800000000",
  "account_type": "employee",
  "display_name": "张三",
  "invite_code": "K7F2QX",
  "captcha_id": "wJ8xQ2mK7pLd",
  "captcha_code": "AB3D",
  "agree_terms": true
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `username` | string | 是 | 唯一 |
| `password` | string | 是 | 由 `auth.create_user` 校验长度等规则 |
| `contact` | string | 是 | 手机号或邮箱，作为登录标识 |
| `account_type` | string | 否 | `employee`（默认）/ `enterprise` |
| `display_name` | string | 否 | 展示名 |
| `invite_code` | string \| null | 否 | 企业邀请码；员工加入企业时必填 |
| `captcha_id` | string | 是 | 来自 `/auth/captcha` |
| `captcha_code` | string | 是 | 不分大小写 |
| `agree_terms` | bool | 是 | 必须为 `true` |

- 三道闸按顺序校验：同意条款 → 联系方式 → 验证码（错误即 400，且该验证码已作废）。
- 响应：

```json
{
  "status": "pending",
  "message": "注册成功，等待企业管理员审核",
  "username": "zhangsan",
  "account_type": "employee",
  "status_label": "待审核"
}
```

`account_type=enterprise` 时 `message` 为 `注册成功，等待系统管理员审核`。

- 错误：400（未同意条款 / 缺联系方式 / 验证码错或过期 / 用户名重复 / 邀请码无效）。

### 3.4 POST `/auth/login`

- 鉴权：无。
- 请求体：

```json
{"account": "admin", "password": "admin123", "remember": true}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `account` | string | 二选一 | 手机号 / 邮箱 / 用户名 |
| `username` | string | 二选一 | 历史字段，等价于 `account` |
| `password` | string | 是 | |
| `remember` | bool | 否 | `true` 发 30 天持久 Cookie；否则浏览器会话 Cookie（默认 7 天服务端会话） |

- 响应头：`Set-Cookie: rag_session=<token>; HttpOnly; SameSite=Lax; Path=/`（`remember=true` 时带 `Max-Age`）。
- 响应体：

```json
{
  "status": "ok",
  "username": "admin",
  "display_name": "管理员",
  "role": "admin",
  "account_status": "active",
  "status_label": "正常",
  "is_system_admin": true,
  "is_enterprise_admin": false
}
```

- 待审核账号**可以登录成功**（返回 `account_status: "pending"`、`status_label: "待审核"`），但业务接口会 403；
- 错误：400（缺账号 / 未启用登录）、401（账号或密码错误、账号状态不允许登录）。

### 3.5 POST `/auth/logout`

- 鉴权：无（未登录也返回 ok）。
- 请求体：无。
- 行为：删除服务端会话 + 清 Cookie（只清 Cookie 不算退出，令牌仍可用，因此必须删库）。
- 响应：

```json
{"status": "ok"}
```

## 4. 问答接口

### 4.1 POST `/qa`

统一问答入口。内部按意图路由：闲聊 → 固定回复；聚合 / 统计 → Text2SQL；其余 → RAG 混合检索 + 精排 + 生成。

- 鉴权：需登录；能力 `answer`。
- 请求体：

```json
{
  "question": "深圳有哪些高价值客户",
  "dept": null,
  "top_k": 3,
  "retriever": "bm25",
  "deep_thinking": false
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `question` | string | 是 | 用户问题 |
| `dept` | string \| null | 否 | 部门过滤。**只有 `ops`（L4）能生效**，其余角色传了也按 `null` 处理 |
| `top_k` | int \| null | 否 | 「返回多少个用户」，范围 `1~30`；无 `topk` 能力（L1）时静默忽略，用默认 `3`；超上限按上限 |
| `retriever` | string \| null | 否 | 关键词召回：`bm25` / `sparse` / `both`；缺省用 `config`（默认 `bm25`） |
| `deep_thinking` | bool \| null | 否 | 深度思考，只作用于最后一次生成调用。实测慢约 5.5 倍、token 约 7.2 倍；`None/false` = 关 |

- 响应（L4 视角，字段按角色裁剪，见 1.6）：

```json
{
  "route": "rag",
  "answer": "深圳的高价值客户主要有 3 位：[来源1] ...",
  "cached": false,
  "sources": [
    {
      "index": 1,
      "source": "画像:张三",
      "text": "张三，深圳，金卡，近 90 天消费 1.2 万元……",
      "origin_query": "深圳 高价值 客户",
      "from_query": "深圳有哪些高价值客户",
      "strategies": ["profile"],
      "rerank_score": 0.8123,
      "expanded": false
    }
  ],
  "rows_count": 12,
  "sql_rows": [["深圳", "12"]],
  "sql": "SELECT city, COUNT(*) FROM user_profile_vectors GROUP BY city",
  "sql_error": null,
  "trace": {
    "variants": [{"strategy": "profile", "query": "深圳 高价值 客户", "hits": 8}],
    "fused_count": 30,
    "limits": {"profile": 3, "wiki": 2},
    "profile_pool_count": 40
  }
}
```

- `route` 取值：`rag`（检索生成）/ `chitchat`（闲聊或域外，固定回复，不调模型）/ `error`（检索基础设施不可用）/ `llm_error`（LLM 接口故障）。
- 走 Text2SQL 时才有 `rows_count` / `sql_rows` / `sql` / `sql_error`。
- 同一问题重复提问（同 `dept` / `retriever` / `top_k` / `deep_thinking` / 数据集）会命中缓存，`cached: true`。比对不同策略前先 `POST /admin/clear-cache`。
- 错误：422（`question` 缺失 / 类型错误，FastAPI 请求模型校验）、401、403。

### 4.2 POST `/qa/stream`

流式问答（SSE）。请求体与 `/qa` **完全相同**，权限也相同（`answer`）。

响应头：

```
Content-Type: text/event-stream
Cache-Control: no-cache
X-Accel-Buffering: no
```

事件格式：`event: <类型>\ndata: <JSON>\n\n`。

| 事件 | data | 说明 |
|---|---|---|
| `stage` | `{"stage": "retrieving"}` / `{"stage": "generating"}` | 阶段提示 |
| `meta` | 见下 | 元信息，**已按角色裁剪** |
| `delta` | `{"delta": "文字片段"}` | 回答正文片段，需按顺序拼接 |
| `reasoning` | `{"delta": "推理片段"}` | 思维链，仅 `deep_thinking=true` 时出现；**不属于回答**，不参与来源引用 |
| `done` | `{}` | 结束 |
| `error` | `{"message": "...", "kind": "llm_unavailable"}` | 出错；`kind` 仅在 LLM 故障时存在 |

`meta` 的 data 示例：

```json
{
  "route": "rag",
  "sources": [{"index": 1, "source": "画像:张三", "text": "..."}],
  "sql": "",
  "rows_count": 0,
  "sql_rows": [],
  "sql_error": null,
  "trace": {},
  "cached": false,
  "deep_thinking": false
}
```

分支行为：

- **缓存命中**：一条 `meta(cached=true)` → 一条 `delta`（全量答案）→ `done`。命中缓存时**不发** `reasoning`（缓存不存思维链）。
- **检索不可用（route=error）**：`meta` → `delta`（兜底文案，对所有角色透出）→ `done`，不写缓存。
- **闲聊（route=chitchat）**：`meta` → `delta` → `done`，并写缓存。
- **正常生成**：`meta` → `stage(generating)` → 若干 `reasoning` / `delta` → `done`，然后写缓存。
- **LLM 故障**：若尚未吐出任何正文，先发一条 `delta`（固定兜底文案），再发 `error(kind=llm_unavailable)`。

注意：服务端**不**对 `delta` 做 `[来源N]` 清理（切片会切断标记），由前端按 `can.sources` 处理。

### 4.3 POST `/search`

仅召回、不生成。同一问题分别走 BM25 与 BGE-M3 稀疏向量，用于对比「为什么 A 找到了而 B 没找到」。

- 鉴权：需登录；能力 `raw_search`（仅 L4）。
- 敏感性：绕过精排与生成直接返回知识库原文片段，是最敏感的接口。
- 请求体：

```json
{"question": "深圳客户", "top_k": 10, "retriever": "bm25"}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `question` | string | 是 | 为空时返回 `{"error": "问题不能为空"}`（200） |
| `top_k` | int | 否 | 默认 10，服务端夹到 `1~50` |
| `retriever` | string \| null | 否 | **当前版本该字段未生效**：接口恒定同时返回 `bm25` 与 `sparse` 两路结果 |

- 响应：

```json
{
  "question": "深圳客户",
  "bm25": [
    {"rank": 1, "source": "画像:张三", "score": 12.34, "text": "张三，深圳，金卡……"}
  ],
  "sparse": [
    {"rank": 1, "source": "画像:张三", "score": 0.87, "text": "张三，深圳，金卡……"}
  ],
  "sparse_note": "",
  "both_hit": ["画像:张三"],
  "only_bm25": ["会员规则.md#金卡"],
  "only_sparse": []
}
```

- `text` 截断 90 字；`sparse_note` 在 FlagEmbedding 未安装或稀疏检索失败时给出原因。

- 注意：构建会 **TRUNCATE + 全量重写** 目标库，不要在有用数据的库上随手调用；构建期间该数据集上的 `/api/wizard/query` 会返回 `route: "busy"`。

### 8.6 GET `/api/wizard/build/{task_id}`

构建进度快照（前端轮询）。

- 响应：

```json
{
  "task_id": "ab12cd34ef56",
  "upload_id": "x7Kp2mQ9aBc1",
  "dataset": "user",
  "status": "running",
  "percent": 46,
  "step_index": 2,
  "steps": [
    {"key": "clean", "label": "清洗交易数据", "unit": "行",
     "status": "done", "percent": 100, "processed": 5000, "total": 5000},
    {"key": "profile", "label": "聚合用户画像", "unit": "个用户",
     "status": "done", "percent": 100, "processed": 616, "total": 616},
    {"key": "embed", "label": "生成画像向量", "unit": "条画像",
     "status": "running", "percent": 52, "processed": 320, "total": 616},
    {"key": "chunk", "label": "切分规则文档", "unit": "篇文档",
     "status": "pending", "percent": 0, "processed": 0, "total": 2},
    {"key": "index", "label": "建立检索索引", "unit": "个分块",
     "status": "pending", "percent": 0, "processed": 0, "total": 0}
  ],
  "processed": 320,
  "total": 616,
  "note": "生成画像向量…",
  "error": null,
  "started_at": 1760000000.0
}
```

- `status`：`running` / `done` / `failed`；
- 步骤 `status`：`pending` / `running` / `done` / `skipped` / `failed`；
- `percent` 上限 99，100 只在 `status=done` 时出现（100 表示「连索引都建完了」）；
- 只保留最近 5 个任务，过期任务返回 404；
- `done` 时额外有 `result`：

```json
{"profiles": 616, "rows": 5000, "index_total": 1234, "elapsed_s": 38.2, "freshness": "fresh"}
```

- `failed` 时 `error` 为原因字符串；`note` 会提示「失败可能留下部分数据，直接重试即可（会先清空再重写）」。

### 8.7 POST `/api/wizard/query`

向导第 4 步的真实问答，与 `/qa` 走**同一条 pipeline**（意图路由 → 多路检索 → 精排 → 生成）。

- 请求体：

```json
{"question": "金卡会员有什么特征", "upload_id": "x7Kp2mQ9aBc1", "dataset": "user"}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `question` | string | 是 | 长度 ≤ 200 字 |
| `upload_id` | string \| null | 否 | 传了就校验批次归属 |
| `dataset` | string | 否 | 默认 `user`；登录态下由账号作用域覆盖 |

- 响应：

```json
{
  "answer": "金卡会员以深圳、杭州为主……",
  "sources": [
    {"index": 1, "source": "画像:张三", "text": "……", "origin_query": "金卡 特征",
     "from_query": "金卡会员有什么特征", "strategies": ["profile"],
     "rerank_score": 0.8123, "expanded": false}
  ],
  "route": "rag",
  "busy": false,
  "cached": false,
  "dataset": "user",
  "elapsed_ms": 8200
}
```

- 与 `/qa` 的差异：**不做按角色裁剪**（向导是独立业务线，操作者就是这批数据的主人，来源片段对他是自查凭据），因此 `sources` 始终是完整字段。
- 整段问答持数据集锁（一次十几秒），因此构建期间会得到：

```json
{
  "answer": "数据集正在重建（画像与检索索引都在重写），构建期间不提供查询。……",
  "sources": [],
  "route": "busy",
  "busy": true,
  "cached": false,
  "dataset": "user",
  "elapsed_ms": 0
}
```

- 问答抛异常（如该数据集从未构建）：`route: "error"`，`answer` 里带原因与「回到第 3 步重新构建」的指引，HTTP 仍为 200。
- 错误：400（问题为空 / 超 200 字 / 数据集非法）、403（批次不属于自己）。

### 8.8 GET `/api/wizard/examples`

根据**已确认的字段**与**上传文件里的真实取值**动态生成示例问题（只出检索类问句）。

- 查询参数：`upload_id`（可选）。
- 响应：

```json
{
  "questions": [
    "会员等级是金卡的用户有什么特征",
    "深圳的用户有什么特征",
    "客单价最高的用户有什么共同点",
    "《会员规则.md》里是怎么规定的"
  ],
  "based_on_fields": ["city", "member_level", "amount"],
  "doc_count": 1
}
```

- 取值来源三档退让、绝不编造：字段映射到列 → 读该列真实取值；读不到 → 用不含具体值的通用问法；字段未映射 → 不出这一条。
- `questions` 最多 5 条。

## 9. 附录

### 9.1 请求头

| 请求头 | 用途 | 生效条件 |
|---|---|---|
| `Cookie: rag_session` | 会话令牌 | 登录后 |
| `X-Role` | 自报角色（`admin`/`exec`/`analyst`/`ops`/`cs`/`guest`） | 仅 `RAG_ALLOW_HEADER_AUTH=1` 且未登录 |
| `X-User` | 自报人员标识（用于人员级提权） | 同上 |
| `Content-Type` | `application/json` / `multipart/form-data` | - |

### 9.2 关键枚举

| 枚举 | 取值 |
|---|---|
| 账号类型 `account_type` | `employee` / `enterprise` |
| 账号状态 `status` | `pending` / `active` / `disabled` / `rejected` |
| 角色 | `admin` / `ent_admin` / `exec` / `analyst` / `ops` / `cs` / `guest` |
| 等级 | `L0`（不可授）/ `L1` / `L2` / `L3` / `L4` |
| 能力 | `answer` / `sources` / `topk` / `internals` / `trace_flow` / `sql` / `stats` / `raw_search` / `ops` / `tenant` |
| 问答 route | `rag` / `chitchat` / `error` / `llm_error` / `busy`（仅向导） |
| 关键词召回 `retriever` | `bm25` / `sparse` / `both` |
| 构建任务状态 | `running` / `done` / `failed` |
| 构建步骤 key | `clean` / `profile` / `embed` / `chunk` / `index` |
| 索引新鲜度 | `fresh` / `stale` / `unknown` |

### 9.3 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `DEEPSEEK_API_KEY` | 无 | 必填，生成与 Text2SQL 都依赖 |
| `RAG_AUTH_ENABLED` | `1` | `0` = 关闭登录态，回到请求头自报身份 |
| `RAG_ALLOW_HEADER_AUTH` | `0` | `1` = 登录态开启时仍接受 `X-Role` / `X-User` |
| `RAG_AUTH_DB` | `var/app.db` | 账号 / 会话 / 企业库（SQLite） |
| `RAG_ADMIN_USER` / `RAG_ADMIN_PASSWORD` | `admin` / `admin123` | 种子系统管理员 |

其他开关见 `src/rag_demo/config.py`：`ENABLE_API_DOCS`、`INTENT_ROUTER`、`TOP_K_PROFILE`、`TOP_K_PROFILE_MIN/MAX`。

### 9.5 测试注意事项

1. **401 与 403 含义不同**：401 = 未登录（前端跳登录页）；403 = 已登录但无权限，或账号待审核 / 停用。两者用户下一步动作不同，别混用。
2. **`X-Role` 默认不生效**：想免登录测多角色，需启动时设 `RAG_ALLOW_HEADER_AUTH=1`；彻底关登录用 `RAG_AUTH_ENABLED=0`。
3. **能力不满足的接口返回 403 且文案统一**为「当前身份无权访问该接口」，不透露被挡住的是什么功能。
4. **缓存会干扰对比**：同一问题的第二次请求 `cached: true`；比对 `retriever` / `deep_thinking` 前先清缓存。
5. **`/search`、`/stats` 需要 L4**；`/admin/*` 中权限与运维接口要求系统管理员（仅登录不够）。
6. **向导 `build` 是破坏性写操作**：会清空并重写目标数据集；首次验证建议用 `dataset: "test"`。
7. **`/api/wizard/query` 持锁十几秒**：同一数据集上并发查询/构建会被 409 或 `route: "busy"` 挡回，这是有意的行为，不是偶发失败。
8. **中文请求体**在 cmd 下容易乱码，建议统一用 `--data-binary "@xxx.json"`（UTF-8 无 BOM）或 PowerShell `Invoke-RestMethod`。
