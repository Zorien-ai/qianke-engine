> **服务**：千客引擎 Demo（问答 / 认证 / 权限 / 账号 / 导入向导）
> **版本**：v1（对应代码 `M3`，2026-10）
> **基准**：`src/rag_demo/api/main.py`、`src/rag_demo/api/wizard.py`、`src/rag_demo/mvp/app.py`
> **编写口径**：路径与字段**保持实现现状**，不做设计变更；与 REST 规范不一致处集中记于 [§1.6](#16-与-rest-规范的差异现状口径)

### 1.2 认证

服务默认开启会话认证（`AUTH_ENABLED=1`，`RAG_ALLOW_HEADER_AUTH=0`）。

1. `POST /auth/login` 校验账号密码，返回 `Set-Cookie: rag_session=<token>`；
2. 后续请求携带该 Cookie；
3. 每个请求由服务端把 Cookie 解析为账号（`auth.resolve_session`），角色与能力**每请求重新计算**。

| 项 | 值 |
|---|---|
| Cookie 名 | `rag_session` |
| 属性 | `HttpOnly; SameSite=Lax; Path=/`；`remember=true` 时附加 `Max-Age`（30 天） |
| 服务端会话有效期 | 7 天（未勾选「记住」）/ 30 天（勾选） |
| 会话存储 | 仅存 token 的 SHA-256（`var/app.db`），库被拷走不能直接登录 |
| 种子管理员 | `admin` / `admin123`（`RAG_ADMIN_USER` / `RAG_ADMIN_PASSWORD` 可覆盖） |

**请求头 `X-Role` / `X-User`**：仅在 `RAG_ALLOW_HEADER_AUTH=1` 且未登录时生效，用于离线脚本演示，**不是安全边界**。

### 1.3 权限模型

角色决定等级，等级决定能力；企业管理员额外持有 `tenant`（身份自带，不受等级影响）。

| 等级 | 能力集合 | 默认角色 |
|---|---|---|
| `L4` | `answer` `sources` `topk` `internals` `trace_flow` `sql` `stats` `raw_search` `ops` | `admin` |
| `L3` | `answer` `sources` `topk` `internals` | `exec`、`ent_admin` |
| `L2` | `answer` `sources` `topk` | `analyst`、`ops` |
| `L1` | `answer` | `cs` |
| `L0` | 无 | `guest` |

| 能力 | 语义 | 影响 |
|---|---|---|
| `answer` | 可提问 | §5 全部端点 |
| `sources` | 可见来源列表（编号 + 来源名） | `sources[]` 是否出现 |
| `topk` | 可调「返回多少个用户」 | `top_k` 是否生效 |
| `internals` | 可见原文片段、精排分数、检索式 | `sources[]` 扩展字段、`trace` |
| `trace_flow` | 可见融合与精排汇总 | `trace.fused_count` / `limits` / `profile_pool_count` / `wiki_doc_dedup` |
| `sql` | 可见 SQL 原文与执行报错 | `sql` / `sql_error` |
| `stats` | 可见数据概况与索引新鲜度 | §6.1、§6.2 |
| `raw_search` | 可只召回不生成 | §5.3 |
| `ops` | 可运维、可覆盖 `dept` | §6.4、§6.5、§7.1–§7.5、`/qa` 的 `dept` |
| `tenant` | 可管本企业成员 | §8 全部端点（企业管理员） |

等级 → 能力的映射可在页面上动态修改，落盘 `var/permissions.json`，**改完不重启即生效**（每个请求重新读配置）。

### 1.4 响应的按角色裁剪

`/qa` 与 `/qa/stream` 的响应由 `permissions.render()` 裁剪：无权限字段**整键移除**（不是置空）。

| 字段 | L1 | L2 | L3 | L4 |
|---|:--:|:--:|:--:|:--:|
| `route` `answer` `cached` | ✓ | ✓ | ✓ | ✓ |
| `sources[].index` `sources[].source` | ✗ | ✓ | ✓ | ✓ |
| `sources[].text` `origin_query` `from_query` `strategies` `rerank_score` `expanded` | ✗ | ✗ | ✓ | ✓ |
| `rows_count` `sql_rows` | ✓ | ✓ | ✓ | ✓ |
| `sql` `sql_error` | ✗ | ✗ | ✗ | ✓ |
| `trace` | ✗ | ✗ | ✓（无 flow 汇总） | ✓（全量） |

附加规则：

- `answer` 正文中的 `[来源N]`：无 `sources` 能力时被移除，`[来源：结构化查询结果]` 这类散文式标注保留；
- `sql_rows` 最多 20 行、每格截断 60 字；`sources[].text` 截断 400 字；
- 缓存存**完整结果**，裁剪只发生在发送前，因此角色不进缓存键。

### 1.5 状态码

| 状态码 | 语义 | 响应体 |
|---|---|---|
| 200 | 成功（含「业务失败但已给出可读文案」的问答分支） | 端点定义的 JSON |
| 302 | 页面重定向到登录页 | 空 |
| 400 | 参数或业务规则校验失败 | `ErrorResponse` |
| 401 | 未登录 | `ErrorResponse` |
| 403 | 已登录但无该能力 / 账号不可用 / 越权访问他方资源 | `ErrorResponse` |
| 404 | 上传批次、构建任务或账号不存在 | `ErrorResponse` |
| 409 | 数据集忙（构建或问答持锁中） | `ErrorResponse` |
| 422 | 请求体不符合模型定义（字段缺失、类型错误） | `ErrorResponse`（FastAPI 校验格式） |
| 500 | 环境或基础设施失败（建库失败、示例数据缺失） | `ErrorResponse` |

`ErrorResponse` 定义见 [§2.1](#21-errorresponse)。

### 1.6 与 REST 规范的差异（现状口径）

本节显式记录「为什么这些端点不是 Stripe 式的 REST 资源」，避免读者误以为是文档疏漏。**本文只描述现状，未做任何路径或字段变更。**

| 端点 | 规范做法 | 现状与原因 |
|---|---|---|
| `POST /qa` | `POST /v1/questions` 或 `POST /v1/answers` | `/qa` 是产品命名，前端与服务端已固化；单数动词路径 |
| `POST /qa/stream` | `POST /v1/answers` + `Accept: text/event-stream` | 内容协商会让「流式 / 非流式」共用路径，但前端已按两条路径实现 |
| `POST /search` | `GET /v1/chunks?query=` | 请求体较长且需避免 URL 编码问题；同时该接口是敏感调试口，用 POST 不易被误缓存 |
| `POST /api/wizard/build` | `POST /v1/imports`，返回 `201 Created` | 构建是**异步任务**，语义上更接近 `202 Accepted`；现状返回 200 + `task_id` |
| `GET /api/wizard/build/{task_id}` | `GET /v1/imports/{import_id}` | 资源名用 `build`，且 `task_id` 是进程内标识（非持久化 ID） |
| `DELETE /admin/permissions/user/{user_id}` | `DELETE /v1/users/{id}/permission`，返回 `204` | 现状返回 200 + 完整配置，便于前端一次拿到最新矩阵 |
| `POST /admin/*` 各写操作 | 子资源 + `PATCH` | 现状以「动作」建模（approve / role / status），比 PATCH 语义更明确 |
| `upload_id` / `task_id` / `user_id` | 不暴露内部标识 | `upload_id` 为 12 位随机串（非自增），`task_id` 为 12 位随机串，`user_id` 在 §8 中为自增整数 |
| 路径大小写 | 全小写 kebab-case | 现状全小写；`/api/wizard` 前缀为历史遗留的分组名 |

## 2. 公共数据结构

以下模型被多个端点引用，避免逐处重复。

### 2.1 `ErrorResponse`

所有 4xx / 5xx（422 除外）的响应体：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `detail` | string | 是 | 可直接展示给用户的中文说明；不泄露内部实现 |

```json
{"detail": "当前身份无权访问该接口"}
```

422 为 FastAPI 请求模型校验格式：

```json
{
  "detail": [
    {"type": "missing", "loc": ["body", "question"], "msg": "Field required", "input": {}}
  ]
}
```

### 2.2 `Source`

`sources[]` 的元素。字段随等级递增（见 [§1.4](#14-响应的按角色裁剪)）。

| 字段 | 类型 | 出现等级 | 说明 |
|---|---|---|---|
| `index` | integer | L2+ | 引用编号，与正文 `[来源N]` 一一对应 |
| `source` | string | L2+ | 来源名（画像 / 文档名#小节） |
| `text` | string | L3+ | 原文片段，最长 400 字 |
| `origin_query` | string | L3+ | 首次召回该条的子查询 |
| `from_query` | string | L3+ | 合并后归并到的子查询 |
| `strategies` | array\<string\> | L3+ | 命中路径，如 `["profile"]`、`["wiki","bm25"]` |
| `rerank_score` | number | L3+ | 精排分数，保留 4 位小数 |
| `expanded` | boolean | L3+ | 是否做过全文扩展 |

### 2.3 `Trace`

L3+ 可见；`fused_count` / `limits` / `profile_pool_count` / `wiki_doc_dedup` 仅 L4 可见。

| 字段 | 类型 | 说明 |
|---|---|---|
| `variants` | array\<object\> | 每路检索的留痕：`strategy`、`query`、`hits` |
| `fused_count` | integer | 融合后候选数（仅 L4） |
| `limits` | object | 各池名额，如 `{"profile":3,"wiki":2}`（仅 L4） |
| `profile_pool_count` | integer | 画像池基数（仅 L4） |
| `wiki_doc_dedup` | integer | 文档去重后条数（仅 L4） |

### 2.7 `UploadBatch`（§9 的批次状态）

| 字段 | 类型 | 说明 |
|---|---|---|
| `upload_id` | string | 12 位十六进制随机串 |
| `csv_files` | array\<CsvFile\> | 表格文件解析结果 |
| `md_files` | array\<MdFileBrief\> | 文档元信息（不含正文） |
| `fields` | array\<FieldSpec\> | 9 个系统字段的识别结果 |
| `docs` | array\<DocAnalysis\> | 文档结构分析 |
| `warnings` | array\<string\> | 面向用户的中文提示（假警告比没有更伤人，故只在确有依据时出现） |
| `summary` | object | `csv_count`、`md_count`、`total_rows`、`total_chunks`、`detected_fields`、`total_fields` |
| `rejected` | array\<string\> | 仅上传 / 示例接口返回：被跳过的文件及原因 |

`CsvFile`：`name`、`size`（字节）、`encoding`（**原始**编码，盘上已转 UTF-8）、`row_count`、`columns`。

`MdFileBrief`：`name`、`size`、`chars`。

`FieldSpec`：`key`、`label`、`required`、`hint`、`detected`、`column`（命中的列名，未命中为 `null`）、`from_file`、`options`（可选列全集）。

`DocAnalysis`：`name`、`size`、`chars`、`h1`、`h2`、`h3`、`total_headings`、`est_chunks`、`warning`。

### 2.8 `BuildTask`（§9.5、§9.6）

| 字段 | 类型 | 说明 |
|---|---|---|
| `task_id` | string | 12 位随机串 |
| `upload_id` | string | 所属批次 |
| `dataset` | string | 目标数据集（`user` / `test` / `ent_<id>`） |
| `status` | string | `running` / `done` / `failed` |
| `percent` | integer | 总进度 0–100（99 为上限，100 只在 `done` 时给出） |
| `step_index` | integer | 当前步骤下标 |
| `steps` | array\<BuildStep\> | 五步：`clean`、`profile`、`embed`、`chunk`、`index` |
| `processed` | integer | 当前步骤已处理量 |
| `total` | integer | 当前步骤总量 |
| `note` | string | 面向用户的一句话状态 |
| `error` | string \| null | 失败原因 |
| `started_at` | number | Unix 时间戳（秒，浮点） |
| `result` | object | 仅 `done`：`profiles`、`rows`、`index_total`、`elapsed_s`、`freshness` |

`BuildStep`：`key`、`label`、`unit`、`status`（`pending` / `running` / `done` / `skipped` / `failed`）、`percent`、`processed`、`total`。

## 5. 问答

### 5.1 创建问答 `POST /qa`

**接口概览** — 统一问答入口。内部按意图路由：闲聊 → 固定回复（不调模型）；聚合 / 统计 → Text2SQL；其余 → 多路检索 + 精排 + 生成。回答与来源来自同一条 pipeline，响应按角色裁剪后才出网。

**请求说明**

| 项 | 值 |
|---|---|
| 方法与路径 | `POST /qa` |
| 鉴权 | 会话 Cookie，能力 `answer`（401 / 403） |
| Content-Type | `application/json` |
| 幂等性 | 否；同参数重复请求会命中缓存（`cached: true`） |
| 典型耗时 | 9–17s（生成占 92–96%） |

**请求参数**

| 参数名 | 类型 | 必填 | 说明 | 示例 |
|---|---|---|---|---|
| `question` | string | 是 | 用户问题，无长度上限 | `深圳有哪些高价值客户` |
| `dept` | string \| null | 否 | 部门过滤。**仅 `ops`（L4）生效**，其余角色一律按 `null` 处理（防止自报越权召回） | `华东` |
| `top_k` | integer \| null | 否 | 「返回多少个用户」，服务端夹到 `1–30`；无 `topk` 能力（L1）时**静默忽略**，用默认 3 | `3` |
| `retriever` | string \| null | 否 | 关键词召回方式：`bm25` / `sparse` / `both`；缺省用服务端配置（`bm25`） | `both` |
| `deep_thinking` | boolean \| null | 否 | 深度思考，仅作用于最后一次生成调用。实测慢约 5.5 倍、token 约 7.2 倍 | `false` |

**响应参数（成功 200）**

| 字段 | 类型 | 出现条件 | 说明 |
|---|---|---|---|
| `route` | string | 恒有 | `rag` / `chitchat` / `error` / `llm_error` |
| `answer` | string | 恒有 | 回答正文；L1 时已移除 `[来源N]` 标记 |
| `cached` | boolean | 恒有 | 是否命中缓存 |
| `sources` | array\<[Source](#22-source)\> | 需 `sources` 能力 | 来源列表，编号与正文引用一致 |
| `rows_count` | integer | 走 SQL 路时 | 结果行数（业务事实，所有可提问角色可见） |
| `sql_rows` | array\<array\<string\>\> | 走 SQL 路时 | 最多 20 行、每格 60 字的原始结果 |
| `sql` | string | 需 `sql` 能力 | 执行的 SQL 原文 |
| `sql_error` | string \| null | 需 `sql` 能力 | SQL 失败原因 |
| `trace` | [Trace](#23-trace) | 需 `internals` 能力 | 检索与规划留痕 |

**响应参数（错误）**

| 状态码 | `detail` | 触发条件 |
|---|---|---|
| 401 | `请先登录` | 强制登录且无有效会话 |
| 403 | `账号待审核：请等待管理员通过后再使用` | 账号状态 `pending` |
| 403 | `该账号已停用` | 账号状态 `disabled` |
| 403 | `当前身份无权访问该接口` | 缺少 `answer` 能力 |
| 422 | FastAPI 校验 | `question` 缺失 |

**业务分支（HTTP 仍为 200）**

| `route` | 含义 | 响应特征 |
|---|---|---|
| `rag` | 正常检索生成 | 有 `sources`；走 SQL 路时另有 `sql*` 字段 |
| `chitchat` | 闲聊 / 域外，不调模型 | `sources: []`，正文为引导文案 |
| `error` | 检索基础设施不可用（数据库等） | `sources: []`，正文为「服务不可用」文案，**不写缓存** |
| `llm_error` | LLM 接口故障（超时 / 限流 / 5xx） | 正文为固定兜底文案，**不写缓存** |

### 5.2 创建流式问答 `POST /qa/stream`

**接口概览** — 与 §5.1 同一 pipeline，改为 SSE 逐字下发。前置检索（约 3–6s）完成后立刻开始输出，**总耗时不变，感知延迟大幅下降**。

**请求说明**

| 项 | 值 |
|---|---|
| 方法与路径 | `POST /qa/stream` |
| 鉴权 | 会话 Cookie，能力 `answer` |
| Content-Type | `application/json` |
| 响应类型 | `text/event-stream`（`Cache-Control: no-cache`、`X-Accel-Buffering: no`） |
| 请求体 | **与 §5.1 完全一致** |

**请求参数**

同 [§5.1 请求参数](#51-创建问答-post-qa)。

**响应参数（事件流）**

每条事件格式为 `event: <类型>\ndata: <JSON>\n\n`：

| 事件 | `data` 结构 | 说明 |
|---|---|---|
| `stage` | `{"stage": "retrieving" \| "generating"}` | 阶段提示 |
| `meta` | 见下表 | 元信息，**已按角色裁剪** |
| `delta` | `{"delta": string}` | 正文片段，需按到达顺序拼接 |
| `reasoning` | `{"delta": string}` | 思维链片段，仅 `deep_thinking=true`；**不属于回答**，不参与 `[来源N]` |
| `replace` | `{"answer": string, "guard": object}` | 后置审查命中：此前下发的正文作废，用 `answer` 整体覆盖渲染（之后仍会收到 `done`） |
| `done` | `{}` | 正常结束 |
| `error` | `{"message": string, "kind"?: "llm_unavailable"}` | 出错；`kind` 仅 LLM 故障时存在 |

`meta` 事件字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `route` | string | 同 §5.1 |
| `sources` | array\<[Source](#22-source)\> | 按角色裁剪；`chitchat` / `error` 分支为空数组 |
| `sql` / `sql_error` | string | 仅 `sql` 能力；无 SQL 路时为空串 / `null` |
| `rows_count` | integer | SQL 结果行数 |
| `sql_rows` | array\<array\<string\>\> | SQL 结果摘要 |
| `trace` | [Trace](#23-trace) | 仅 `internals` 能力；否则为空对象 |
| `cached` | boolean | 是否命中缓存 |
| `deep_thinking` | boolean | 回显请求值（非裁剪项：它是请求方自己的输入） |

**事件序列（四种分支）**

| 分支 | 序列 |
|---|---|
| 缓存命中 | `meta(cached=true)` → `delta`（全量正文）→ `done`；**不发** `reasoning` |
| 检索不可用 | `meta(route=error)` → `delta`（兜底文案，对所有角色透出）→ `done`；不写缓存 |
| 闲聊 | `meta(route=chitchat)` → `delta` → `done`；写缓存 |
| 正常生成 | `meta` → `stage(generating)` → (`reasoning` / `delta`)* → `done`；写缓存 |
| 正常生成 + 审查命中 | `meta` → `stage(generating)` → (`reasoning` / `delta`)* → `replace`（固定文案）→ `done`；缓存写**替换后**的答案 |
| LLM 故障 | 若尚未输出正文：`delta`（固定兜底文案）→ `error(kind=llm_unavailable)`；已输出过则只发 `error` |

**错误**

| 状态码 | `detail` | 触发条件 |
|---|---|---|
| 401 / 403 | 同 §5.1 | 未登录 / 待审核 / 缺能力 |
| 422 | FastAPI 校验 | 请求体不合法 |

流内错误不走 HTTP 状态码，通过 `error` 事件通知。

**示例**

```bash
curl -sN -X POST http://127.0.0.1:8000/qa/stream \
  -H "Content-Type: application/json" \
  -b ck.txt \
  -d '{"question":"深圳有哪些高价值客户","top_k":3}'
```

```
event: stage
data: {"stage": "retrieving"}

event: meta
data: {"route": "rag", "sources": [{"index": 1, "source": "画像:张三", "text": "张三，深圳，金卡……"}], "sql": "", "rows_count": 0, "sql_rows": [], "sql_error": null, "trace": {}, "cached": false, "deep_thinking": false}

event: stage
data: {"stage": "generating"}

event: delta
data: {"delta": "深圳的高价值客户主要有 3 位："}

event: delta
data: {"delta": "[来源1] 张三（金卡）……"}

event: done
data: {}
```

> 服务端不对 `delta` 做 `[来源N]` 清理（切片会切断标记），由前端按 `can.sources` 处理。

### 7.2 保存权限配置 `PUT /admin/permissions`

**接口概览** — 整份保存「等级 → 能力」与「角色 → 等级」。校验失败返回 400 且**不落盘**：宁可整体拒绝，也不写进去一半。

**请求说明**

| 项 | 值 |
|---|---|
| 方法与路径 | `PUT /admin/permissions` |
| 鉴权 | 会话 Cookie + 系统管理员 |
| Content-Type | `application/json` |
| 语义 | **全量替换** `levels` 与 `role_levels`；`user_levels` 传 `null` 表示保留现状 |
| 并发 | 读-改-写全程持锁，后写覆盖前写（不返回 409） |

**请求参数**

| 参数名 | 类型 | 必填 | 说明 | 示例 |
|---|---|---|---|---|
| `levels` | object\<string, array\<string\>\> | 是 | 等级 → 能力列表；缺省等级按代码默认补齐 | `{"L1":["answer"]}` |
| `role_levels` | object\<string, string\> | 是 | 角色 → 等级 | `{"cs":"L1"}` |
| `user_levels` | object \| null | 否 | `null` / 缺省 = 保留现有人授权；传对象 = **整体替换** | `null` |

约束：能力名必须是 `CAP_LABELS` 中的键；等级必须是 `L1`–`L4`；角色必须是 `ROLES` 中的键；`guest` 固定 `L0`。

**响应参数（成功 200）**

| 字段 | 类型 | 说明 |
|---|---|---|
| `status` | string | 固定 `"saved"` |
| `config` | object | 保存后的完整配置（结构见 §7.1） |

**响应参数（错误）**

| 状态码 | `detail` | 触发条件 |
|---|---|---|
| 400 | `权限配置必须是对象` / `levels 必须是 {等级: [能力]} 结构` / `L1 的能力清单必须是数组` / `未知能力: xxx` / `角色非法: xxx` | 归一化校验失败 |
| 401 / 403 | 同 §7.1 | 未登录 / 非系统管理员 |
| 422 | FastAPI 校验 | `levels` 或 `role_levels` 缺失 |

**示例**

```bash
curl -s -X PUT http://127.0.0.1:8000/admin/permissions \
  -H "Content-Type: application/json" -b ck.txt \
  -d '{
    "levels": {
      "L1": ["answer"],
      "L2": ["answer", "sources", "topk"],
      "L3": ["answer", "sources", "topk", "internals"],
      "L4": ["answer", "sources", "topk", "internals", "trace_flow", "sql", "stats", "raw_search", "ops"]
    },
    "role_levels": {"admin": "L4", "exec": "L3", "analyst": "L2", "ops": "L2", "cs": "L1"},
    "user_levels": null
  }'
```

```json
{
  "status": "saved",

    "version": 4,

    "user_levels": {},
    "updated_at": "2026-10-17 11:20:00",
    "updated_by": "admin"
  }
}
```

### 7.3 单点授权 `POST /admin/permissions/grant`

**接口概览** — 给某个角色改默认等级，或给某个人员单独设等级（覆盖角色等级，立刻生效）。

| 项 | 值 |

**请求参数**

|---|---|---|---|---|
| `target_type` | string | 是 | `role` 改角色默认等级；`user` 改指定人员 | `user` |
| `target` | string | 是 | 角色名或用户名（`user` 模式下会 trim） | `zhangsan` |
| `level` | string | 是 | `L1`–`L4`，大小写不敏感；`L0` / `guest` 不可授予 | `L4` |

| 状态码 | `detail` | 触发条件 |
|---|---|---|
| 400 | `等级非法: X（可选 L1/L2/L3/L4）` | `level` 不合法 |

| 400 | `未识别身份固定为 L0，不能授予等级` | 试图给 `guest` 授权 |
| 400 | `用户 ID 不能为空` | `target_type=user` 且 `target` 为空白 |
| 400 | `target_type 只能是 role / user，收到 'xxx'` | 类型非法 |
| 401 / 403 | 同 §7.1 | 未登录 / 非系统管理员 |

**示例**

### 9.5 启动构建任务 `POST /api/wizard/build`

**接口概览** — 异步构建：清洗交易 → 聚合画像 → 生成画像向量 → 切分文档 → 建检索索引。接口立即返回 `task_id`，前端轮询 §9.6。

**两种构建模式**（第五轮起）：
- `incremental`（**默认**）追加更新：只处理本批次里**新增/变更**的 CSV 与 MD，只更新新文件里出现的用户
  （已有用户按聚合字段合并、新用户新增，**未涉及的用户一行都不动**），检索索引只增删受影响行。
  大数据量客户日常追加几秒~几分钟即可完成，不需要为一个小文件全量重算。
- `full` 覆盖重建：TRUNCATE 后全量重写（旧版行为）。适合首次构建、换了整套数据、或增量被判不可用时。

增量是否可用、本次会处理哪些文件，先调 `GET /api/wizard/plan`（§9.11）查询；构建进度里也能看到 `mode`。

**请求说明**

| 项 | 值 |
|---|---|
| 方法与路径 | `POST /api/wizard/build` |
| 鉴权 | 会话 Cookie + 批次归属 |
| Content-Type | `application/json` |
| 幂等性 | **否**：每次调用都生成新的 `task_id`；并发时由数据集锁或 409 挡住 |
| 破坏性 | `full`：**是**（TRUNCATE + 全量重写）；`incremental`：只更新受影响用户/文档，未涉及数据不动 |

**请求参数**

| 参数名 | 类型 | 必填 | 说明 | 示例 |
|---|---|---|---|---|
| `upload_id` | string | 是 | 批次号 | `x7Kp2mQ9aBc1` |
| `fields` | object\<string, string\> | 否 | 字段 key → 上传文件中的列名；有 CSV 时 `user_id` 必填 | `{"user_id":"用户ID","amount":"订单金额"}` |
| `mode` | string | 否 | `incremental`（默认）/ `full`；其它值 400 | `incremental` |
| `dataset` | string | 否 | 旧参数：登录态下**不采纳**（数据集由账号推导），保留仅为兼容旧脚本 | `test` |
| `simulate_failure` | boolean | 否 | 演示用：在「生成画像向量」一步故意失败，验证可读报错与重试 | `false` |

**响应参数（成功 200）**

| 字段 | 类型 | 说明 |
|---|---|---|
| `task_id` | string | 12 位任务号，用于轮询进度 |
| `dataset` | string | **实际写入**的数据集（由登录账号推导） |
| `mode` | string | 本次实际使用的构建模式 |

**响应参数（错误）**

| 状态码 | `detail` | 触发条件 |
|---|---|---|
| 400 | `构建模式只能是 incremental 或 full` | `mode` 非法 |
| 400 | `本批次没有新增文件可追加；要重算全部数据请选「覆盖重建」` | `incremental` 但没有新增/变更文件（会附同名改内容的 CSV 名单） |
| 400 | `该数据空间由旧版本构建，无法判断哪些文件已入库；请先做一次「覆盖重建」…` | 数据集有数据但无清单、也没有可引导的 last_build |
| 400 | `当前数据空间还没有构建过（或数据已清空）…` | 空库上使用 `incremental` |
| 400 | `「用户ID」还没选对应的列。…` / `没有可构建的数据…` | 必填字段未映射 / 批次内无文件 |
| 403 | `无权访问该上传批次` | 批次不属于当前账号 |
| 404 | 由 `uploads.paths` 抛出 | 批次不存在 |
| 409 | `数据集 xxx 正忙：…` | 数据集锁被占用 |
| 500 | `数据空间准备失败：...` | 企业库首次建库失败 |
| 401 / 403 | 登录闸门 | 未登录 / 待审核 |

### 9.7 向导内问答 `POST /api/wizard/query`

**接口概览** — 第 4 步的真实问答，与 §5.1 同一条 pipeline。相比 `/qa` 只多做两件事：切到本批数据所在的数据集；整段问答持有该数据集锁（避免读到「改到一半的数据」）。

**请求说明**

| Content-Type | `application/json` |

### 10.2 清空数据空间 `POST /api/kb/clear`

**接口概览** — 清空**当前账号所属租户**的整个数据空间（画像 + 文档 + 检索索引），不可恢复。
目标库只能由登录账号推导：`confirm` 只做「与推导出的库名比对」，请求体里写别的库名不会生效。

**请求说明**

| 项 | 值 |
|---|---|
| 方法与路径 | `POST /api/kb/clear` |
| 鉴权 | 会话 Cookie + **企业管理员**（系统管理员对 `demo` 只读，员工无权限） |
| Content-Type | `application/json` |
| 幂等性 | 否（已空再清返回 409） |

**请求参数**

| 参数名 | 类型 | 必填 | 说明 | 示例 |
|---|---|---|---|---|
| `confirm` | string | 是 | 必须等于当前数据空间名（二次确认） | `"ent_21"` |

**响应参数（成功 200）**

| 字段 | 类型 | 说明 |
|---|---|---|
| `status` | string | 固定 `"cleared"` |
| `dataset` | string | 被清空的数据空间 |
| `cleared` | object | 清理前的真实计数：`{profiles, chunks, docs, index}` |

清空后保留：`last_build`（重建来源）、`ui_*` 文案配置、`doc_source_dir`（文档原文目录）。
删掉的是语料指纹类 meta 键，因此概况页会显示 `built_at=null`、`freshness=unknown`。

**响应参数（错误）**

| 状态码 | `detail` | 触发条件 |
|---|---|---|
| 400 | `二次确认不匹配：…请在确认框里输入当前数据空间名称「ent_21」再试` | `confirm` 与推导出的库名不一致 |
| 401 | `请先登录` | 无会话 |
| 403 | `演示数据集是评测基线，只读，不能清空；…` / `只有企业管理员可以清空数据` | 系统管理员 / 员工 |
| 409 | `当前租户数据为空，无需清空` / `数据集正忙：…` | 数据本来就空 / 构建或问答持有数据集锁 |

**示例**

```bash
curl -s -b ck.txt -X POST http://127.0.0.1:8000/api/kb/clear \
  -H "Content-Type: application/json" -d '{"confirm":"ent_21"}'
```

```json
{"status": "cleared", "dataset": "ent_21",
 "cleared": {"profiles": 5, "chunks": 2, "docs": 1, "index": 7}}
```

### 10.3 重置企业邀请码 `POST /admin/enterprise/invite-code/reset`

**接口概览** — 生成新的 8 位邀请码（去掉 0/O/1/I 等易混字符）。**旧码立即失效**（注册按库实时查码，无缓存）。

**请求说明**

| 项 | 值 |
|---|---|
| 方法与路径 | `POST /admin/enterprise/invite-code/reset` |
| 鉴权 | 会话 Cookie + 企业管理员 / 系统管理员 |
| Content-Type | `application/json`（可无请求体） |
| 幂等性 | 否（每次生成新码） |

**请求参数**

| 参数名 | 类型 | 必填 | 说明 | 示例 |
|---|---|---|---|---|
| `enterprise_id` | integer | 系统管理员必填；企业管理员忽略 | 要重置哪家企业 | `3` |

**响应参数（成功 200）**

| 字段 | 类型 | 说明 |
|---|---|---|
| `enterprise.id` | integer | 企业 ID |

| `enterprise.dataset` | string | 企业库名 `ent_<id>` |
| `enterprise.invite_code` | string | 新的 8 位邀请码 |

**响应参数（错误）**

### 11.1 请求头

### 11.5 测试注意事项

1. **401 与 403 语义不同**：401 = 未登录（跳登录页）；403 = 已登录但无能力，或账号待审核 / 停用。前端据此决定下一步动作。
2. **`X-Role` 默认不生效**：默认强制登录。多角色测试需启动前设 `RAG_ALLOW_HEADER_AUTH=1`（保留登录）或 `RAG_AUTH_ENABLED=0`（彻底关闭）。
3. **缓存会干扰对比**：同一问题的第二次请求会 `cached: true`；比对 `retriever` / `deep_thinking` 前先调 `POST /admin/clear-cache`。
4. **`/search` 与 `/stats` 需要 L4**；`/admin/*` 中的运维与权限端点要求**系统管理员**，仅登录不够。
5. **向导 `build` 是破坏性写操作**，会清空并重写目标数据集；首次验证用 `dataset: "test"`。
6. **向导 `query` 整段持锁**：同一数据集上并发构建 / 查询会被 409 或 `route: "busy"` 挡回，属预期行为。
7. **`user_id` 含义在不同端点不同**：§7.4 是用户名（string），§8.x 是账号自增 ID（integer）。
8. **`/qa` 的业务失败也是 200**（`route=error` / `llm_error` / `chitchat`），不要只按 HTTP 状态码判断成败。
9. **首次请求慢**：模型在启动时预加载；若启动阶段先起了请求，会等到加载完成。

### 11.6 与 OpenAPI 的关系

`GET /openapi.json` 由 FastAPI 自动生成，是**结构真源**（字段类型、必填、422 结构）。本文档在此之上补充了自动生成无法表达的信息：

| 本文档补充的内容 | 自动生成文档缺少的原因 |
|---|---|
| 按角色的响应裁剪矩阵 | 裁剪发生在 `permissions.render()` 运行时，不在模型声明里 |
| 业务分支（`route=busy` / `error` 仍为 200） | 由端点的返回值决定，不在状态码声明里 |
| 错误 `detail` 的具体文案与触发条件 | `HTTPException` 动态构造 |
| 副作用与幂等性（TRUNCATE、持锁、缓存） | 不属于接口签名 |
| 示例中的真实响应 | FastAPI 不生成 example |

生产环境应设 `ENABLE_API_DOCS=False`，此时 `/docs`、`/redoc`、`/openapi.json` 全部关闭，本文档成为唯一的外部说明。
