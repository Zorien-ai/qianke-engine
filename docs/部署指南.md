# 部署指南

> 目标：从一台干净机器启动「千客引擎」，并说明生产化前必须补齐的边界。
> 本地快速开始见根目录 [README](../README.md#quick-start)。

## 1. 运行拓扑

```
Browser
  └─ Vue 3 (web/dist, 由 FastAPI 挂载到 /v2/)
       └─ FastAPI (uvicorn)
            ├─ PostgreSQL 16 + pgvector
            │    ├─ vec_db              演示/评测基线
            │    ├─ vec_db_user         用户数据集
            │    ├─ vec_db_test         测试首跑库
            │    └─ vec_db_ent_<id>     每个企业一个物理库
            ├─ rag_auth                 账号 / 会话 / 企业 / 上传归属
            ├─ BGE-M3 / bge-reranker    本地模型权重（约 7 GB）
            └─ DeepSeek API             LLM 生成 / 评测裁判
```

`docker-compose.yml` **只负责 PostgreSQL + pgvector**。模型推理在后端进程内完成；
生产环境可以把 API 进程放进容器，但请把模型目录以只读卷挂载，避免镜像膨胀。

## 2. 端口与依赖

| 组件 | 默认 | 说明 |
|---|---|---|
| API | `8000` | FastAPI / 前端静态资源 |
| PostgreSQL | `5432` | `pgvector/pgvector:pg16` |
| 模型目录 | `./models/bge-m3`、`./models/bge-reranker-v2-m3` | 不入库，需下载 |
| Python | 3.12 | `requires-python = ">=3.12,<3.13"` |
| Node | 20+ | 仅构建 `web/` 需要 |

## 3. 本地部署

### 3.1 数据库

```bash
cp .env.example .env        # 可选：compose 会用 .env 做变量插值
docker compose up -d
docker compose ps           # 必须看到 (healthy)
```

默认库名/用户/密码：`vec_db` / `postgres` / `123456`。如需修改：

1. 改 `.env` 中的 `POSTGRES_*`；
2. 同步改 `src/rag_demo/config.py` 的 `DB_CONFIG`（向量库连接目前不是环境变量驱动）；
3. 同步改 `.env` 的 `RAG_AUTH_PG_PASSWORD`（认证库连接）。

首次启动 API 会创建认证表与默认管理员；**首次启动前**请通过
`RAG_ADMIN_USER` / `RAG_ADMIN_PASSWORD` 改掉默认账号。

### 3.2 Python 环境

```bash
uv sync --frozen        # 按 uv.lock 安装（推荐）
# 或 uv sync           # 允许按 pyproject 更新解析
```

模型权重不随仓库分发，放到 `config.py` 约定的目录：

```bash
uv run python - <<'PY'
from huggingface_hub import snapshot_download
snapshot_download("BAAI/bge-m3", local_dir="models/bge-m3")
snapshot_download("BAAI/bge-reranker-v2-m3", local_dir="models/bge-reranker-v2-m3")
PY
```

> 国内网络可使用 ModelScope 下载同名模型后放到相同目录。
> 微调意图分类器（`src/rag_demo/bert_query_classify/`）是可选项：目录缺失时
> 路由自动回退到关键词规则，服务仍可启动。

### 3.3 导入数据 / 建索引

```bash
uv run python src/rag_demo/ingest_data.py
uv run python src/rag_demo/ingest_docs.py
uv run python src/rag_demo/tools/build_search_index.py
uv run python src/rag_demo/tools/check_search_index.py
```

`search_index` 与源表没有自动失效机制：**每次重导画像/文档后都必须重建索引**，
否则查询会静默使用旧索引。

### 3.4 前端与启动

```bash
cd web
npm ci
npm run build
cd ..
uv run uvicorn rag_demo.api.main:app --host 0.0.0.0 --port 8000
```

访问 <http://127.0.0.1:8000>（302 → `/v2/`），或 `/docs` 查看 OpenAPI。
`web/dist/` 不入库；换机器后必须重新构建。

### 3.5 环境变量

本项目**不会隐式加载 `.env`**；`.env.example` 是变量清单。启动前请导出到进程环境，
或使用 systemd/容器 `env_file`。最少需要：

```bash
export DEEPSEEK_API_KEY="sk-..."
```

完整变量与默认值见 [`.env.example`](../.env.example) 与
`src/rag_demo/config.py`、`src/rag_demo/auth.py`。生产必须至少修改：

| 变量 | 为什么必须改 |
|---|---|
| `DEEPSEEK_API_KEY` | 不要提交真实 key |
| `RAG_ADMIN_PASSWORD` | 默认 `admin123` 只适用于本地 |
| `RAG_SQL_READONLY_PASSWORD` | 只读账号密码 |
| `RAG_AUTH_PG_PASSWORD` | 认证库密码 |
| `RAG_ALLOW_HEADER_AUTH` | 生产必须为 `0`，禁止 `X-Role`/`X-User` 覆盖身份 |
| `RAG_AUTH_ENABLED` | 生产应为 `1` |

### 3.6 图片存储（可选，阿里云 OSS）

文档正文里的 `![架构图](images/arch.png)` 要"人能看到图"，需要对象存储。
**不配置也能正常跑**：文档照常切分入库，只是不保存图片，检索结果里没有配图。

#### 为什么是私有桶 + 签名 URL

知识库图片属于租户数据，Bucket 权限保持 **private**。读图不用公共地址，而是每次响应
时 `presign` 一个临时地址（默认 30 分钟）；数据库与回答缓存里**只存 object key**，
否则命中缓存（TTL 1 小时）拿到的会是过期地址。

#### 1) 创建 RAM 子账号（不要用主账号 AK）

控制台 → 访问控制 RAM → 用户 → 创建用户 → 勾选「OpenAPI 调用访问」，保存
AccessKey ID / Secret（Secret 只显示一次）。再建自定义策略，只授权目标前缀：

```json
{
  "Version": "1",
  "Statement": [{
    "Effect": "Allow",
    "Action": ["oss:PutObject", "oss:GetObject", "oss:AbortMultipartUpload", "oss:ListParts"],
    "Resource": ["acs:oss:*:*:your-bucket/kb/*"]
  }]
}
```

把策略绑定到该用户，Bucket 读写权限选**私有**。

#### 2) 注入环境变量

| 变量 | 必填 | 说明 |
|---|---|---|
| `RAG_OSS_BUCKET` | 是 | bucket 名 |
| `RAG_OSS_ACCESS_KEY_ID` | 是 | 也接受 `OSS_ACCESS_KEY_ID`（官方 SDK 同名变量） |
| `RAG_OSS_ACCESS_KEY_SECRET` | 是 | 也接受 `OSS_ACCESS_KEY_SECRET` |
| `RAG_OSS_REGION` | 否 | 默认 `cn-hangzhou` |
| `RAG_OSS_ENDPOINT` | 否 | 默认 `https://oss-<region>.aliyuncs.com` |
| `RAG_OSS_PREFIX` | 否 | 对象公共前缀，默认 `kb/` |
| `RAG_OSS_SIGN_EXPIRE` | 否 | 签名有效期（秒），默认 `1800` |

三个必填项缺任意一个 → 图片功能整体关闭，日志会写明缺哪个；文档照常入库。

#### 3) 图片怎么进知识库

- **随 md 一起传**：正文写 `![](images/arch.png)`，同批把图片上传（浏览器多选会被
  扁平化到批次目录，引用写成 `assets/x.png` 也能按文件名匹配到）。
- **独立上传**：`POST /api/wizard/upload-image`，返回 `key` 与可直接粘进正文的
  `![name](oss://kb/inline/202610/xxx.png)`。
- **外链**：`https://...` 原样透传，不下载转存。

检索命中包含该引用的 chunk 时，`sources[].images` 会带上 `{alt, url, key}`，
`url` 是当次现签的临时地址（需要 L3「内部」能力才看得到）。

#### 4) 父块回填粒度

`RAG_WIKI_PARENT_MODE`：

| 值 | 行为 |
|---|---|
| `section`（默认） | 命中的 chunk 回填为所属**标题章节**（入库时写 `parent_text`，上限 1600 字） |
| `doc` | 旧行为：回填整篇文档（`WIKI_MAX_CHARS` 截断） |
| `off` | 不回填，只用命中的 chunk |

父块在**入库时**生成，改完需要重跑 `ingest_docs.py` + `build_search_index.py` 才生效；
老库首次启动会由 `ensure_wiki_columns()` 自动补 `parent_key` / `parent_text` 列。

> 注意：重建不会删除已删文档的 OSS 图片对象（孤儿对象需靠 Bucket 生命周期规则清理）。

## 4. 生产化检查清单

- [ ] 反代 + TLS（Nginx/Caddy），只暴露 443；uvicorn 只监听内网
- [ ] 改默认管理员密码；删除/停用演示账号
- [ ] `RAG_ALLOW_HEADER_AUTH=0`、`RAG_AUTH_ENABLED=1`
- [ ] PostgreSQL 不开公网；强密码；定期备份；卷不随代码发布
- [ ] 模型目录只读挂载；不进入镜像/仓库/LFS
- [ ] Text2SQL 使用只读账号；确认 `sql_reader` 只能 SELECT
- [ ] `config.ENABLE_API_DOCS=False`（如不需要 OpenAPI）
- [ ] 关闭 `DEFAULT_API_ROLE="admin"` 的过渡默认值（见 `config.py` 注释）
- [ ] 企业租户库创建/迁移走运维流程；不要把 `vec_db_ent_*` 混用
- [ ] 监控 `/health`、SQL 报错率、LLM 超时率、评测门禁结果
- [ ] 日志不落 API Key、Cookie、完整手机号/身份证号

## 5. 资源与性能

- 模型权重约 7 GB；BGE-M3 + reranker 推理建议至少 16 GB 内存，GPU 可显著降低延迟。
- 单次问答典型耗时数秒；离线全量评测约 3~4 分钟（33 题，含裁判调用）。
- 首次启动会加载模型与 BM25 语料；预热完成前请求较慢，建议接 readiness 检查。
- 并发高时按进程/GPU 显存做限流；不要把模型加载放在每个 worker 内重复执行。

## 6. 排错

| 现象 | 优先检查 |
|---|---|
| 所有问题都答「资料缺失」 | `docker compose ps` 是否 healthy；检索是否连到空库 |
| 启动即报模型找不到 | `models/bge-m3`、`models/bge-reranker-v2-m3` 是否存在 |
| 修改数据后答案不变 | 是否重跑 `build_search_index.py`；看 `check_search_index.py` |
| `/v2/` 404 | 是否执行 `cd web && npm run build` |
| 登录 401/403 | Cookie、`RAG_AUTH_ENABLED`、账号状态；生产不要启用 header auth |
| 评测无法判分 | `DEEPSEEK_API_KEY` 是否在进程环境；裁判模型是否可用 |
| 上传报错 | `data/uploads/` 写权限、批次归属（`upload_owner`） |

## 7. 升级与回滚

1. 先备份 `rag_auth` 与企业库（`pg_dump`）；
2. `uv sync` / `npm ci && npm run build`；
3. 启动时 `ensure_schema()` 幂等建表，不会自动删除列；
4. 若涉及画像/文档数据变更，重跑导入与索引重建；
5. 回滚代码后如 schema 已扩展，旧版本通常可忽略新增列；破坏性迁移需显式脚本。

更细的接口、权限与租户行为见 [接口文档](接口文档.md) 与 [数据模型](数据模型.md)。
