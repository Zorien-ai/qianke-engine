# **电商用户行为分析数据集**

[电商用户行为分析数据集_数据集-阿里云天池](https://tianchi.aliyun.com/dataset/216886)

### 描述

该数据集是一个模拟的中文电商用户行为数据集，共包含1000条交易记录。 主要内容： 用户信息：包含用户ID、随机生成的中文姓名、性别、年龄及分布在全国各地的城市信息。 商品信息：涵盖电子产品、服装、家居等7大类商品，每类包含具体的商品名称及单价。 交易细节：包括购买时间（2024年全年）、购买数量及自动计算的消费总金额。 适用场景： 此数据集结构清晰，非常适合用于电商数据分析练习，例如用户画像构建、地域消费习惯分析、热销商品统计以及RFM模型（最近一次消费、消费频率、消费金额）的实战演练。 我已经将其保存为 6个主流电商平台的模拟交易数据集，每个数据集均包含1000条2024年度的中文交易记录。数据集涵盖天猫（高端B2C，价格高5%）、淘宝（综合C2C，标准价格）、京东（品质自营，价格高2%）、拼多多（社交拼团，价格低15%）、苏宁易购（线上线下融合）和1688（批发采购平台）六大平台。每个数据集包含12个核心字段，覆盖用户维度（ID、姓名、性别、年龄、城市）、商品维度（ID、名称、类别、单价）和交易维度（购买时间、数量、金额）。数据覆盖电子产品、服装、家居等7大类目，用户分布于全国12个主要城市，年龄段18-65岁。所有数据集采用统一的CSV格式（UTF-8 BOM编码），可直接用于Excel、Python、Tableau等工具进行跨平台对比分析、用户画像构建、RFM模型分析、销售趋势预测等电商数据分析实战演练。 文件在您的工作区中。

# 电商平台用户行为分析数据集详细说明

## 1. 数据集概述

本项目包含6个主流电商平台的模拟用户行为数据集，专为电商领域的数据分析、用户画像构建及业务洞察挖掘而设计。每个数据集包含1000条模拟的中文电商交易记录，旨在还原真实的电商交易场景。通过这些数据集，分析师可以模拟从数据清洗、探索性数据分析（EDA）到深度业务建模的全过程，同时支持跨平台对比分析，洞察不同平台的经营特征和用户行为差异。

### 1.1 平台列表及特征

| 平台名称     | 定位         | 价格策略        | 目标用户                       |
| :----------- | :----------- | :-------------- | :----------------------------- |
| **天猫**     | 高端B2C平台  | 比市场均价高5%  | 中高端消费群体，注重品牌和品质 |
| **淘宝**     | 综合C2C平台  | 标准市场价格    | 各类消费人群，商品种类最丰富   |

| **拼多多**   | 社交拼团平台 | 比市场均价低15% | 价格敏感型消费者，追求性价比   |

## 2. 数据字段字典

本数据集包含12个核心字段，覆盖了用户、商品、交易三个维度的关键信息：

### 用户维度 (User Dimension)

- **用户ID (用户ID)**: 用户的唯一标识符（格式：U1000-U9999），用于区分不同用户。
- **用户姓名 (用户姓名)**: 随机生成的中文真实姓名，基于常见百家姓和名字组合，用于模拟个性化展示。
- **用户性别 (用户性别)**: 用户的性别（男/女），用于性别偏好分析和用户画像构建。
- **用户年龄 (用户年龄)**: 用户的年龄数据，覆盖18-65岁，均匀分布，用于年龄段特征分析。
- **用户城市 (用户城市)**: 用户所在的中国主要城市，包括北京、上海、广州、深圳、成都、杭州、武汉、西安、南京、重庆、天津、苏州等12个城市，用于地域分布分析。

### 商品维度 (Product Dimension)

- **商品ID (商品ID)**: 商品的唯一标识符（格式：P10000-P99999）。
- **商品名称 (商品名称)**: 具体的商品中文名称，涵盖7大类目下的多种商品。
- **商品类别 (商品类别)**: 商品所属的一级分类，共7大类：电子产品、服装、家居、书籍、美妆、运动、玩具。
- **单价 (单价)**: 商品的单件销售价格（人民币），根据类别和平台定位设定，符合市场常规价格区间。

### 交易维度 (Transaction Dimension)

- **购买时间 (购买时间)**: 交易发生的具体时间点（精确到秒），随机分布于2024年全年（2024-01-01至2024-12-31），适合进行时间序列分析（如月度销售额、季度趋势、下单高峰时段）。
- **购买数量 (购买数量)**: 单次订单中购买该商品的数量（1-5件）。
- **消费金额 (消费金额)**: 订单的总金额（单价 × 数量），是计算GMV（商品交易总额）和客单价的基础。

## 4. 适用场景与分析价值

该数据集具有极高的实战价值，适用于以下分析场景：

### 4.1 单平台分析

1. **用户画像 (User Profiling)**: 结合性别、年龄、城市数据，构建用户标签体系，识别核心用户群体。
2. **RFM模型分析**: 利用最近一次购买时间（Recency）、消费频率（Frequency）和消费金额（Monetary）对用户价值进行分层，识别高价值客户。
3. **畅销与滞销分析**: 统计不同品类、不同商品的销量排名，辅助库存管理决策和营销策略制定。
4. **地域消费差异**: 对比不同城市的消费能力与偏好差异，为区域化运营提供数据支持。
5. **时间趋势分析**: 分析全年销售额的波动趋势，识别销售旺季和淡季，优化营销活动时机。

### 4.2 跨平台对比分析

1. **价格竞争力分析**: 对比同类商品在不同平台的价格差异，分析各平台的价格定位策略。
2. **用户群体差异**: 对比不同平台的用户年龄、性别、地域分布，识别各平台的目标用户特征。
3. **品类侧重分析**: 分析不同平台在各商品类别的销售占比，发现各平台的经营特色。
4. **客单价对比**: 对比各平台的平均订单金额，评估用户消费能力和购买习惯差异。

## 7. 实测补充：`user_id` 不是用户实体键（2026-10-16）

本文档第 2 节把 `用户ID` 描述为「用户的唯一标识符（格式：U1000-U9999），
用于区分不同用户」，但**实测与这一描述不符**——它是逐行独立随机生成的数字：

| 检验 | 结果 |
|---|---|
| 跨平台同名 ID 的属性一致性 | 抽样 2000 个，**2000 个全部冲突**（姓名 / 性别 / 年龄 / 城市） |
| 平台内重复 ID 的属性一致性 | 同样 100% 冲突（天猫 52/52、1688 55/55、ecommerce_data 4441/4441） |
| `(用户ID, 用户姓名)` 组合数 | = 21000 = 总行数（ID 不携带身份信息） |
| 每个 ID 的行数分布 | 与「21000 次随机抽样落在 9000 个 ID 上」的理论分布几乎重合（实际 distinct 8110 vs 理论 8127） |

**结论**：不能按 `user_id` 聚合出「一个用户的交易历史」。本仓库因此把所有
画像表述改为**聚合样本口径**（见 `README.md`「数据口径」一节）。

另外两点实测：

1. `ecommerce_data.csv` **不在本说明书登记的 6 个平台之列**：它与 6 个平台文件的
   行级重叠为 0 / 1000（既不是合并也不是超集），15000 行占全量 71%，唯一商品
   13802 而平台文件各约 994。现已不再被当作平台名，统一记为「未标注来源」
   （见 `ingest_data.py::KNOWN_PLATFORMS`）。
2. `消费金额 = 单价 × 购买数量`，一行 = 一次单品购买记录；CSV **无订单号**，
   因此 `order_count` 实为「购买记录行数」，不是订单数。
