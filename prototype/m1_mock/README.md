# prototype/m1_mock —— M1 交互原型的冻结快照（8001）

这是 M1（用假数据跑通「上传 → 确认 → 构建 → 查询」）在 2026-10-16 的完整快照，
**原样冻结**，供内测环境继续使用。

## 启动（项目根目录下执行）

```bash
uv run uvicorn m1_mock.app:app --port 8001 --app-dir prototype
```

- 页面：<http://127.0.0.1:8001/>（四步向导）
- 探针：<http://127.0.0.1:8001/health>

**URL 与端口与冻结前完全一致**，测试者手上的链接不会断。唯一变化是启动命令多了
`--app-dir prototype`（因为快照搬出了 `src/rag_demo/`）。

## 为什么会有这个目录

`src/rag_demo/mvp/app.py` 的原设计是「M2 把 mock 实现换成真实实现，前端一行不用改」——
也就是说，M2 第一天就会改到**真人测试环境正在跑的那份文件**：页面在测试者眼皮底下变化，
出了问题也分不清是「新代码的 bug」还是「正在改的中间态」。

所以把 M1 整体复制一份冻结出来：8001 只认这份快照，M2 在 `src/` 里随便动。

## 冻结到什么程度

整个目录**不 import `rag_demo` 的任何模块**（连切分器都复制了一份，
见 `split_estimate.py` 的说明）。依赖只有 `fastapi` / `pydantic` / `langchain-*`，
启动毫秒级，不需要模型、不需要数据库。

| 文件 | 说明 |
|---|---|
| `app.py` | 路由与 mock 实现（原 `src/rag_demo/mvp/app.py`） |
| `mock_data.py` | 假数据与字段识别同义词字典（原样复制） |
| `split_estimate.py` | 切分逻辑的冻结副本，只服务「预估分块数」 |
| `static/` | 向导页三件套（`wizard.html` / `wizard.css` / `wizard.js`） |

## 纪律

- **不要在这里做 M2 的迭代**。要改界面或逻辑，改 `src/rag_demo/mvp/`（那是 M2 的迭代区），
  或新代码写进 `src/rag_demo/api/`（8000）。
- 不要为了「和真实实现保持同步」而修改本目录。快照的价值是稳定，不是最新。
- 本目录的寿命 = 内测环境（8001）的寿命。它退役时整目录可以删掉。
