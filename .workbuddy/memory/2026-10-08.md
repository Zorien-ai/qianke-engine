## 踩坑与结论（可复用）

1. **Mermaid 分层架构图不能用模块级跨层箭头定层序。** 原方案给每层 subgraph 加 `direction LR` + 模块级依赖箭头，结果：① 有跨层边时 `direction` 被 Mermaid 忽略；② 层内用 `-->` 会把同层节点拆到不同 rank；③ 无任何边的层（基础设施层）位置随机（跑到顶部）。
   **正解**：层内用 `~~~`（invisible link）串节点保持同 rank 横向并排；层间只连相邻层 `L5 --> L4 --> L3 ...`（subgraph-to-subgraph）；层内不画任何有向边。实测层序 100% 可控。

2. **依赖图用 `flowchart TB` 而非 `LR`。** LR 时汇聚点（config.py）被挤到最右，8 条入边绕行成团；TB 后收敛到底部，交叉大幅减少。

3. **Chrome 无头可用，Edge 无头在本机被静默拦截。** `msedge.exe` 任何参数下 rc=0 / stdout 空 / 无产物（沙箱内与非沙箱皆然）；`chrome.exe --headless=new --no-sandbox --dump-dom` 正常。
   **Edge 路径**：`C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe`；**Chrome 路径**：`C:/Program Files/Google/Chrome/Application/chrome.exe`

4. **Mermaid 节点文本里的 `<` / `>` 用数字实体 `#60;` / `#62;` 最稳**（写 `&lt;` 在 HTML 的 `<pre class="mermaid">` 内会被浏览器先解码成裸 `<`，Mermaid 解析失败）。`<=>` 写作 `#60;=#62;`，`Σ` 直接写。

5. **jsdelivr / unpkg / cdnjs 直连都慢且会超时**（3.3 MB 要数分钟），但**前缀字节一致**，可校验 sha16 后从任一 CDN 用 Range 续传补齐。最终用 unpkg 的 Range 补到 3,335,717 字节，`new Function(src)` 语法校验通过。代理 7890 当时未开。

## 代码核对结论（与需求描述不符，已在图中按代码修正）

| 项 | 需求描述 | 实际代码 |
|---|---|---|
| `generation/generator.py` | 依赖 config | **只 import os + openai**，不依赖 config |
| `api/main.py` | 依赖 config | **不 import config**，只 import db/generation/retrieval |
| `retrieval/hybrid_retriever.py` → `reranker.py` | 存在依赖 | **彼此不 import**，平级，由 main 依次调用 |
| `config.py` 被依赖 | 被所有模块依赖 | 被 **5 个**模块直接 import（db、retrieval×2、ingest×2） |

其余核对一致：TOP_K_VECTOR=20 / TOP_K_BM25=20 / TOP_K_RRF=30 / rrf k=60 / top_k_profile=3 / top_k_wiki=2 / sensitivity<=3 / temperature=0.3 / text[:100] / lifespan 预加载 / get_conn 每次 SELECT 1 探活。
