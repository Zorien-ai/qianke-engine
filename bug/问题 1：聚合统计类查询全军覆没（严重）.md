案例 DA-04「美妆用户的客单价分布」、MGT-01「本周高价值用户规模有多少」、
OPT-05「高客单和普通用户的偏好差异」、OPT-06「母婴偏好用户在哪些城市集中」

现象：这类问题要的是「数量 / 分布 / 占比 / 排名」，RAG 返回的是语义相近的
文本片段，算不了 COUNT / GROUP BY / AVG，只能凑一段描述，数字不可信。

根因：向量检索 + 生成这条链路天然做不了聚合——它给的是「哪段话像」，
不是「算出来的数」。

解决方向：补一条 Text2SQL 链路（tools/sql_tool.py）
    自然语言 → LLM 生成 SQL → 安全校验 → 执行 → 结果自然语言化

关键设计：
- 意图路由先按关键词分流，聚合类问题直接走 SQL，不进检索
- SQL 生成用 temperature=0，保证同一问题稳定出同一条 SQL
- 生成后必须过 4 道安全关才执行：必须 SELECT/WITH 开头、禁用词黑名单、
  必须带 LIMIT、表白名单（CTE 别名自动排除）
- 执行加 statement_timeout=10s，并在 finally 里显式 rollback，
  避免慢查询拖垮连接、连接挂事务阻塞 DDL
- 结果总结时注入表结构（含字段取值范围）——只有注入了，0 行时才说得出
  「数据里没有这个类别」，而不是笼统的「没有符合条件的记录」

现状：已解决。4 条 SQL 题全部走通。
OPT-06 因为 top_category 枚举里没有「母婴」，改为说明数据缺口
——这本身就是正确的回答（用户能区分「数据缺失」和「查询写错了」）。
