# DeepSeek API 故障导致两轮评测白跑

> 日期：2026-10-14 ~ 10-15 ｜ 类型：外部依赖故障 ｜ 状态：已加固（预检 + NaN 告警）

## 现象

2026-10-14 下午，DeepSeek API 出现故障（**后经确认是 API 侧问题**）。故障期间启动了两轮评测，全部白跑：

| 评测 | 表现 |
|---|---|
| 忠实度评测（eval_faithfulness）首跑 | 3 题全失败，`APITimeoutError: Request timed out` / `Connection error`——**串行调用也超时** |
| RAGAS 首跑 | 批量评测里大批样本失败；`raise_exceptions=False` 把失败**静默记成 NaN**，均值照样算得出来 |

两轮都在跑完后才发现，数据作废。

## 我当时的误判（记下来避免再犯）

第一反应把 RAGAS 的 NaN 归因为「ragas 默认 `max_workers=16`，并发打爆 API」，
并据此把并发降到 2。**这个结论下得太满**：

- 忠实度首跑是**串行**调用也连续超时——那才是 API 故障的直接证据，
  当时就摆在日志里，却没有被当作第一证据。
- 正确归因：**API 故障是根因，高并发只是放大器**。
  API 正常时 16 并发未必有事；API 抖动时，16 路必然比 2 路更容易撞上失败。
- 降并发依然是对的（降低了故障期的损失面、也让正常期更稳），
  但它治的是放大器，不是根因。

与 P9 的教训正好构成一对：

- **P9**：把内部问题（思考模式）误判成「外部不可控」，于是停止追查——错。
- **本次**：把外部问题（API 故障）误判成「并发太高」，忙着改内部参数——也错。
- 共同点：**两次都在没有充分证据时就给了归因**。
  「第一次失败是串行还是并发」这个问题，日志里就有答案。

## 影响的数据（结论：最终交付的不受影响）

| 产出 | 跑的时候 API 状态 | 有效性 |
|---|---|---|
| RAGAS 首轮（上下文相关性一半 NaN） | 故障中 | 已作废删除 |
| 忠实度 v19（97.0%） | 跑前诊断 3/3 正常，33/33 成功 | **有效** |
| RAGAS v2（四指标，零 NaN） | API 恢复后，33 题 × 4 指标无缺失 | **有效** |

## 加固（2026-10-15 实施）

1. **`tests/preflight.py`：评测前 API 预检**
   - 探测 2 次成功即放行，最多 4 次；不通立即退出，不启动评测。
   - `timeout=20` + `max_retries=0`：openai SDK 默认内部重试 2 次，
     一次 20s 超时的尝试实际等 60s，4 次就是 4 分钟（实测 257.6s）。
     关掉 SDK 内部重试后，API 挂起时 **9.1s** 就能判定不可用。
   - 已接入 `run_eval.py` / `eval_faithfulness.py` / `eval_ragas.py` 三个入口。

2. **RAGAS 跑完后 NaN 告警**
   - `raise_exceptions=False` 会静默吞掉失败样本，均值照样算得出来——
     那是对「部分样本」的均值，不能当全量结论。
   - 现在逐指标报告 NaN 数，>0 就明确提示「均值只代表有效样本」。

3. 检索自检（`eval_faithfulness.py` 已有）：检索不可用直接退出，
   避免拿空资料评出漂亮的 100%。

## 遗留风险

- 预检只保证**开跑这一刻** API 是通的。跑十几分钟的批量评测中途 API 再挂，
  仍靠 NaN 告警兜底——那是事后发现，不是事前阻止。
  要真正做到「中途挂掉立即停」，需要评测过程按题落盘 + 失败计数熔断。
- API 故障期间服务（uvicorn）同样不可用：用户提问会报错。
  已有 `RETRIEVAL_UNAVAILABLE_REPLY` 区分「检索基础设施挂了」，
  但 LLM 挂了走的是异常路径，返回的是 `流式问答失败`，用户体验不一致。

## 教训

1. **归因前先看日志里最直接的证据**：串行调用也超时，这一条就足以否掉
   「并发太高」的主假设。我看到了它，却没有第一时间用它。
2. **外部因素 ≠ 不可行动**。API 确实不在我们控制之内，但「故障期间不要
   白跑 20 分钟」完全在我们控制之内——这就是预检的价值。
3. **会静默失败的开关最危险**：`raise_exceptions=False` 让坏数据看起来
   像正常数据。任何「失败即记空值」的机制，都必须配一个跑完后的空值告警。
