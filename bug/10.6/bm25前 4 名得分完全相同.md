## 为什么 BM25 在你的语料上退化了

不只是"公共模板词"的问题。你的画像文本是强模板化语料——8110 条文本几乎共享同一套句式：

```text
用户{U}（{name}）：{age}岁{gender}，{city}人。累计订单{N}笔，总消费{X}元，
平均客单价{Y}元，偏好品类为{cat}。最近一次购买在{date}，活跃平台：{plat}。
```

BM25 的本质是 TF-IDF 加权的词频匹配。当语料里 100% 的文档都包含「累计订单」「平均客单价」「最近一次购买」 时：

- 这些词的 IDF 趋近于 0（区分度为零）
- 但它们的 TF 很高（每篇都出现）
- BM25 的 TF 饱和曲线使得这些"公共词"仍然贡献了相近的分数

结果就是你看到的：多篇文档得分完全相同，因为区分度高的词（"美妆""女性"）在 BM25 的字符级匹配里几乎没被加权，而公共词被打了个满堂彩。

这不是 BM25 不行，是语料不适合字符级 BM25。三个根治方向：

| 方向 | 效果 | 工作量 |
|---|---|---|
| 停用词表 | 快速止血，去掉公共词后区分度立刻显现 | 5 分钟 |

## 停用词优化实现

在 `hybrid_retriever.py` 里加：

```python
STOPWORDS = {
    "用户", "累计", "订单", "总消费", "消费", "平均", "客单价", "偏好",
    "品类", "最近", "一次", "购买", "活跃", "平台", "元", "笔", "在",
    "人", "岁", "的", "了", "为", "：", "，", "。", "（", "）", "｜",
}

def _tokenize(text):
    import jieba
    tokens = jieba.lcut(text)
    return [t for t in tokens if t.strip() and t not in STOPWORDS]
```

然后把 `bm25_search` 里的 `list(query)` 和 `_load_bm25_corpus` 里的 `list(t["text"])` 都改成 `_tokenize(...)`。

改完后 BM25 单独 Top-5 应该会变成「女性+美妆」主导，RRF 融合质量也会顺带提升，reranker 的压力变小。
